模型编辑#

Model Editing

备注

本页由 AI（Claude Sonnet）根据 MuJoCo 官方英文文档（2026-11-16 版）翻译，仅供学习参考；如有出入，以英文原版为准。术语对照见资料包中的 术语表.md 。

可以使用 mjSpec 结构体及相关 API 来创建和修改模型（model）。该数据结构与 MJCF 一一对应，实际上，MuJoCo 自带的 XML 解析器（包括 MJCF 和 URDF）在加载模型时也使用这套 API。

It is possible to create and modify models using the mjSpec struct and related API. This data structure is in one-to-one correspondence with MJCF and indeed, MuJoCo’s own XML parsers (both MJCF and URDF) use this API when loading a model.

概述#

Overview

该 API 对传统的“使用 XML 文件创建和编辑模型”的工作流进行了扩展，将 解析 和 编译 两个步骤拆分开来。正如 概览一章 中所总结的，传统工作流如下：

The API augments the traditional workflow of creating and editing models using XML files, breaking up the parse and compile steps. As summarized in the Overview chapter, the traditional workflow is:

  1. 创建 XML 模型描述文件（MJCF 或 URDF）及相关资产。

    Create an XML model description file (MJCF or URDF) and associated assets.

  2. 调用 mj_loadXML，得到一个 mjModel 实例。

    Call mj_loadXML, obtain an mjModel instance.

使用 mjSpec 的工作流如下：

The workflow using mjSpec is:

  1. 使用 mj_makeSpec 创建一个空的 mjSpec，或使用 mj_parseXML 解析现有的 XML 文件。

    Create an empty mjSpec using mj_makeSpec or parse an existing XML file using mj_parseXML.

  2. 通过添加、修改和删除元素，以编程方式编辑 mjSpec 数据结构。

    Programmatically edit the mjSpec data structure by adding, modifying, and removing elements.

  3. 使用 mj_compile 将 mjSpec 编译为 mjModel 实例。

    Compile the mjSpec to an mjModel instance using mj_compile.

编译之后，mjSpec 仍然可以编辑，因此步骤 2 和步骤 3 可以互换。

After compilation, the mjSpec remains editable, so steps 2 and 3 are interchangeable.

模型解析与加载#

Model Parsing & Loading

如 模型实例 中所总结的，模型描述文件（MJCF、MJZ、URDF、USD）通过 mj_parse （在 Python 中为 mjSpec.from_file() / mjSpec.from_string() ）被解析为 mjSpec。模型格式根据内容类型或文件扩展名推断，并将解析为 mjSpec 的工作委托给相应的 解码器 插件（plugin）。

As summarized in Model instances, model description files (MJCF, MJZ, URDF, USD) are parsed into an mjSpec using mj_parse (or mjSpec.from_file() / mjSpec.from_string() in Python). The model format is inferred from the content type or file extension, and parsing into an mjSpec is delegated to the appropriate decoder plugin.
char error[1000] = "";
mjSpec* spec = mj_parse(vfs, "robot.xml", NULL, NULL, error, sizeof(error));

为方便起见，mj_loadXML （或 Python 中的 MjModel.from_xml_path() ）将解析和编译合并为一步，直接从 XML 文件或 .mjz 归档文件返回编译好的 mjModel。

For convenience, mj_loadXML (or Python MjModel.from_xml_path()) combines parsing and compilation into a single step, returning a compiled mjModel directly from an XML file or .mjz archive.

另外，也可以使用 mj_loadModel （或 Python 中的 MjModel.from_binary_path() ）直接从二进制 MJB 文件加载预编译的 mjModel。

Alternatively, a pre-compiled mjModel can be loaded directly from a binary MJB file using mj_loadModel (or Python MjModel.from_binary_path()).

模型编译#

Model Compilation

一旦创建了高层的 mjSpec （通过解析文件、加载归档文件或以编程方式构造），就可以使用 mj_compile 将其编译为 mjModel。

Once a high-level mjSpec is created—by parsing a file, loading an archive, or constructing it programmatically—it is compiled into an mjModel using mj_compile.

编译与加载相互独立，无论 mjSpec 是如何构造的，编译的工作方式都完全相同。解析器和编译器都会执行大量错误检查，并在遇到第一个错误时中止。解析器使用自定义模式（schema）来验证文件结构、元素和属性，而编译器则应用语义检查，并执行一步测试仿真以捕获运行时错误。

Compilation is independent of loading, working in the exact same way regardless of how mjSpec was constructed. Both the parser and the compiler perform extensive error checking and abort when the first error is encountered. The parser uses a custom schema to validate file structure, elements, and attributes, while the compiler applies semantic checks and executes a test simulation step to catch runtime errors.

解析和编译都极其迅速，通常不到一秒，这使得交互式模型设计、实时编辑和快速重新加载变得流畅自然。

Parsing and compilation are extremely fast—typically less than a second—making interactive model design, live editing, and rapid reloading seamless.

模型编码与保存#

Model Encoding & Saving

模型规格（spec）和编译后的模型可以使用 mj_encode 序列化到文件，或使用 mj_saveXMLString 或 mj_saveXML 直接保存为 XML 字符串。

Model specs and compiled models can be serialized to files using mj_encode, or directly saved to XML strings using mj_saveXMLString or mj_saveXML.

mj_encode 函数为模型序列化提供了统一的入口：

The mj_encode function provides a unified entry point for serializing models:
char error[1024] = "";
mjtSize bytes_written = mj_encode(spec, model, "robot.mjz", NULL, vfs, error, sizeof(error));

输出格式根据文件扩展名（不区分大小写）或显式给出的 content_type 自动选择：

The output format is selected automatically based on the file extension (case-insensitive) or explicit content_type:

  • MJCF XML （ .xml ）：使用 mj_saveXML 将 spec 展平为单个 MJCF XML 文件。如果显式传入了 mjModel 参数，mj_encode 会在保存之前将 mjModel 中被修改的值复制回 spec。在计算章节中，我们给出了一个 MJCF 文件的 示例 以及对应的 保存后的示例。

    MJCF XML (.xml): Flattens the spec into a single MJCF XML file using mj_saveXML. If an explicit mjModel argument is passed, mj_encode will copy modified values back from mjModel into the spec prior to saving. In the Computation chapter we show an example MJCF file and the corresponding saved example.

  • MJZ 归档文件 （ .mjz 或 .zip ）：通过内置的 mjz_encoder ，将 spec 及所有相关的外部资产（网格、纹理、被包含的 XML）打包为自包含的 Zip 归档文件。

    MJZ Archive (.mjz or .zip): Bundles the spec and all associated external assets (meshes, textures, included XMLs) into a self-contained Zip archive via the built-in mjz_encoder.

  • MJB 二进制 （ .mjb ）：通过 mj_saveModel 以 MuJoCo 二进制格式序列化编译后的 mjModel。MJB 文件是独立的，不引用外部文件，加载速度比 XML 更快，但与版本绑定，且无法反编译回 XML。需要已编译的 model ；不会 序列化 spec 中的任何内容。

    MJB Binary (.mjb): Serializes the compiled mjModel in MuJoCo binary format via mj_saveModel. MJB files are standalone, do not refer to external files, and load faster than XML, but are version-specific and cannot be decompiled back to XML. Requires a compiled model; does not serialize anything from spec.

  • TXT （ .txt ）：通过 mj_printModel 写出人类可读的文本转储。适用于差异比较和调试。需要已编译的 model ；不会 序列化 spec 中的任何内容。

    TXT (.txt): Writes a human-readable text dump via mj_printModel. Useful for diffing and debugging. Requires a compiled model; does not serialize anything from spec.

spec 以 MJCF 形式保存有两种方式，由其编译器属性 savecompiled 选择：

A spec is saved as MJCF in one of two ways, selected by its compiler attribute savecompiled:

  • "true"（默认值）：保存上一次编译得到的模型值，采用规范表示法。例如，与其自由关节 对齐 的刚体（body）以对齐后的位姿保存，而拟合到网格的 geom 则以拟合得到的尺寸保存。spec 必须已经编译过。

    “true”, the default: the values which the last compilation made of the model, in the canonical notation. For example a body which is aligned with its free joint is saved with its aligned pose, and a geom which was fitted to a mesh with the size of the fit. The spec must have been compiled.

  • "false"：按 spec 中书写的方式保存模型。位姿是元素在其 坐标系 中的位姿，以默认值书写的属性会被保留，每个数值都被精确保存。朝向、角度和 fromto 以书写时所用的表示法保存，除非 savecanonical 为 "true"。spec 无需已经编译。

    “false”: the model as it is written in the spec. Poses are those of the elements in their frames, attributes which were written with their default values are kept, and every number is saved exactly. Orientations, angles and fromto are saved in the notation in which they were written, unless savecanonical is “true”. The spec need not have been compiled.

在这两种情况下，保存的文件都会编译为同一个模型，但 MJCF 无法表达 spec 所保存内容的情况除外。例如，被挂接模型的元素使用其自身的编译器设置进行编译，而保存的文件只有一个 compiler 元素。按书写方式保存时，被挂接模型的角度单位和欧拉序列会被转换，而如果某个设置不同且会改变编译所推断的内容，例如 inertiafromgeom，则会报错并给出说明；按编译值保存时，这样的模型编译结果可能不同。解析器没有保存在 spec 中的内容不会被保存：文件顶部那条注释之外的其他注释、include 元素，以及会被展开为其他元素的元素，例如 replicate、flexcomp、attach 和执行器（actuator）快捷方式。

In both cases the saved file compiles to the same model, except where MJCF cannot say what the spec holds. For example, the elements of an attached model are compiled with its own compiler settings, while the saved file has one compiler element. Saved as written, the angle unit and the Euler sequence of an attached model are converted, and a difference in a setting which changes what compilation infers, such as inertiafromgeom, is an error which says so; saved as compiled values, such a model may compile differently. What the parser does not keep in a spec is not saved: comments other than the one at the top of the file, the include elements, and the elements which it expands into others, such as replicate, flexcomp, attach and the actuator shortcuts.

按书写方式保存的 spec 在两种情况下需要先编译。编译所计算出的惯性（inertial）由 saveinertial 保存，它们是上一次编译的结果，因此必须在任何结构性编辑（添加、删除或挂接元素）之后重新编译，这与按编译值保存时相同。另外，等待编译的 关键帧 （keyframe）——例如在 mjs_attach 或 mjs_delete 改变了含有关键帧的 spec 的运动学树（kinematic tree）之后——会在编译组装好它们的向量之后才被保存。

A spec which is saved as written needs a compilation in two cases. The inertials which compilation calculates, which saveinertial saves, are those of the last compilation, which must follow any structural edit (elements added, deleted or attached), as for compiled values. And keyframes which await compilation, as they do once mjs_attach or mjs_delete changed the kinematic tree of a spec which has keyframes, are saved once compilation has assembled their vectors.

需要注意的是，保存的 XML 会考虑所有已定义的默认值。当模型中有大量重复值时，这一点很有用，例如从不支持默认值的 URDF 加载的模型。在这种情况下，可以添加默认类（default class），设置相关元素的类，然后保存；得到的 XML 将使用这些默认值，可读性更好。

Importantly, saved XML will take into account any defined defaults. This is useful when a model has many repeated values, for example if loaded from URDF, which does not support defaults. In such a case one can add default classes, set the class of the relevant elements, and save; the resulting XML will use the defaults and be more human-readable.

MJZ 归档文件#

MJZ Archives

复杂的 MuJoCo 模型通常由多个文件组成：一个主 MJCF XML 文件、被包含的 XML 子树，以及外部资产文件（网格、纹理、高度场）。MJZ 格式（扩展名 .mjz 或 .zip ）提供了一种便捷的方式，可将整个模型及其引用的所有资产打包为单个 Zip 归档文件。

Complex MuJoCo models often consist of multiple files: a main MJCF XML file, included XML sub-trees, and external asset files (meshes, textures, height fields). The MJZ format (extension .mjz or .zip) provides a convenient way to bundle an entire model and all of its referenced assets into a single Zip archive.

根 XML 文件的查找#

Root XML Discovery

解码 .mjz 归档文件时，MuJoCo 按以下顺序查找根模型 XML 文件：

When decoding an .mjz archive, MuJoCo searches for the root model XML file in the following order:

  1. 归档文件根目录下的 model.xml 。这是 MJZ 编码器 生成的默认格式，也是可移植性最好的选项。

    model.xml at the root of the archive. This is the default format produced by the MJZ encoder and is the most portable option.

  2. 归档文件根目录下的 <archive_stem>.xml （例如 my_model.mjz 内的 my_model.xml ）。

    <archive_stem>.xml at the root of the archive (e.g. my_model.xml inside my_model.mjz).

  3. 与归档文件同名的顶层目录内的 <archive_stem>/<archive_stem>.xml （例如 my_model/my_model.xml ）。

    <archive_stem>/<archive_stem>.xml inside a top-level directory matching the archive name (e.g. my_model/my_model.xml).

  4. 与归档文件同名的顶层目录内的 <archive_stem>/model.xml （例如 my_model/model.xml ）。

    <archive_stem>/model.xml inside a top-level directory matching the archive name (e.g. my_model/model.xml).

选项 2 到 4 是为了向后兼容旧版归档文件和常见的 zip 打包布局而存在的，但如果归档文件被重命名，则容易失败。

Options 2-4 exist for backwards compatibility with legacy archives and common zip packaging layouts, but are susceptible to failure if the archive file is renamed.

自定义格式#

Custom formats

可以使用 mjp_registerDecoder 和 mjp_registerEncoder 添加对新文件格式的支持。当对非原生的扩展名或内容类型调用 mj_parse 和 mj_encode 时，会通过 mjp_findDecoder 和 mjp_findEncoder 找到相应的插件。关于编写自定义格式插件的更多细节，参见 解码器 和 编码器。

Adding support for new file formats can be done with mjp_registerDecoder and mjp_registerEncoder. When mj_parse and mj_encode are called for a non-native extension or content type, the appropriate plugins are found via mjp_findDecoder and mjp_findEncoder. For further details on writing custom format plugins, see Decoders and Encoders.

用法#

Usage

这里我们介绍用于程序化模型编辑的 C API，但它同样在 Python 绑定 中提供。高级用户可以参考 user_api_test.cc 以及 xml_native_reader.cc 中的 MJCF 解析器，以获得更多用法示例。在创建新的 mjSpec 或将现有 XML 文件解析为 mjSpec 之后，程序化编辑就对应于设置属性。例如，要更改时间步长（timestep），可以这样做：

Here we describe the C API for procedural model editing, but it is also exposed in the Python bindings. Advanced users can refer to user_api_test.cc and the MJCF parser in xml_native_reader.cc for more usage examples. After creating a new mjSpec or parsing an existing XML file to an mjSpec, procedural editing corresponds to setting attributes. For example, in order to change the timestep, one can do:
mjSpec* spec = mj_makeSpec();
spec->opt.timestep = 0.01;
...
mjModel* model = mj_compile(spec, NULL);

长度可变的属性是 C++ 的向量和字符串，它们 以不透明类型的形式暴露给 C。在 C 中，使用所提供的 getter 和 setter：

Attributes which have variable length are C++ vectors and strings, exposed to C as opaque types. In C one uses the provided getters and setters:
mjs_setString(spec->modelname, "my_model");

在 C++ 中，可以直接使用向量和字符串：

In C++, one can use vectors and strings directly:
std::string modelname = "my_model";
*spec->modelname = modelname;

模型元素#

Model elements

与 MJCF 对应的模型元素以带有 mjs 前缀的 C 结构体形式暴露给用户。其定义列在结构体参考的 模型编辑 一节下。例如，MJCF 的 geom 对应于 mjsGeom。

Model elements corresponding to MJCF are exposed to the user as C structs with the mjs prefix. The definitions are listed under the Model Editing section of the struct reference. For example, an MJCF geom corresponds to an mjsGeom.

所有元素的全局默认值由 mjs_defaultGeom 等 初始化函数 设置。这些函数定义在 user_init.c 中，是所有默认值的权威来源。

Global defaults for all elements are set by initializers like mjs_defaultGeom. These functions are defined in user_init.c and are the source of truth for all default values.

元素不能直接创建；它们由相应的构造函数返回给用户，例如 mjs_addGeom。例如，要向世界刚体（world body）添加一个盒状 geom，可以这样做：

Elements cannot be created directly; they are returned to the user by the corresponding constructor function, e.g. mjs_addGeom. For example, to add a box geom to the world body, one would do
mjSpec* spec = mj_makeSpec();                                  // make an empty spec
mjsBody* world = mjs_findBody(spec, "world");                  // find the world body
mjsGeom* my_geom = mjs_addGeom(world, NULL);                   // add a geom to the world
my_geom->type = mjGEOM_BOX;                                    // set geom type
my_geom->size[0] = my_geom->size[1] = my_geom->size[2] = 0.5;  // set box size
mjModel* model = mj_compile(spec, NULL);                       // compile to mjModel
...
mj_deleteModel(model);                                         // free model
mj_deleteSpec(spec);                                           // free spec

传给 mjs_addGeom 的第二个参数 NULL 是可选的默认类指针。以程序方式使用默认值时，默认类需要显式传入元素构造函数。所有元素的全局默认值（未传入默认类时使用）可以在 user_init.c 中查看。

The NULL second argument to mjs_addGeom is the optional default class pointer. When using defaults procedurally, default classes are passed in explicitly to element constructors. The global defaults of all elements (used when no default class is passed in) can be inspected in user_init.c.

元素通过名称引用，名称通过 mjs_setName 设置。资产也不例外：通过 mjs_addMesh、mjs_addTexture 或 mjs_addHField 添加的网格、纹理或高度场必须指定名称，即使它是从文件加载的。在省略名称时以资产的文件名为其命名，只是 XML 解析器提供的一种便利功能。

Elements are referenced by name, and names are set with mjs_setName. Assets are no exception: a mesh, texture or height field added with mjs_addMesh, mjs_addTexture or mjs_addHField must be given a name, even when it is loaded from a file. Naming an asset after its file when the name is omitted is a convenience of the XML parser only.

内存管理#

Memory management

如上面的示例所示，模型元素从不由用户直接分配，而是由构造函数返回。库拥有所有元素的所有权，并在使用 mj_deleteSpec 删除父级 mjSpec 时释放它们。用户只需负责释放 mjSpec 结构体。

As seen in the examples above, model elements are never allocated by the user directly, but rather returned by a constructor. The library takes ownership of all elements and frees them when the parent mjSpec is deleted using mj_deleteSpec. The user is only responsible for freeing mjSpec structs.

挂接#

Attachment

该框架引入了一项强大的新功能：挂接和删除模型子树。这一功能已被用于实现 MJCF 中的 attach 和 replicate 元元素（meta-element）。挂接允许用户将一个模型中的子树移动或复制到另一个模型中，同时复制或移动相关的被引用资产，以及来自运动学树之外的引用元素（例如执行器和传感器）。类似地，删除子树会从模型中移除所有相关联的元素。默认行为（“浅拷贝”）是在挂接时将子级移入父级，因此之后对子级的更改也会改变父级。或者，用户可以在挂接时使用 mjs_setDeepCopy 选择生成一份全新的副本。解析 XML 时，该标志会被临时设置为 true。可以 将刚体或 mjSpec 挂接到坐标系：

This framework introduces a powerful new feature: attaching and deleting model subtrees. This feature is already used to power the attach and replicate meta-elements in MJCF. Attachment allows the user to move or copy a subtree from one model into another, while also copying or moving related referenced assets and referencing elements from outside the kinematic tree (e.g., actuators and sensors). Similarly, deleting a subtree will remove all associated elements from the model. The default behavior (“shallow copy”) is to move the child into the parent while attaching, so subsequent changes to the child will also change the parent. Alternatively, the user can choose to make an entirely new copy during attach using mjs_setDeepCopy. This flag is temporarily set to true while parsing XMLs. It is possible to attach a body or an mjSpec to a frame:
mjSpec* parent = mj_makeSpec();
mjSpec* child = mj_makeSpec();
parent->compiler.degree = 0;
child->compiler.degree = 1;
mjsElement* frame = mjs_addFrame(mjs_findBody(parent, "world"), NULL)->element;
mjsElement* body = mjs_addBody(mjs_findBody(child, "world"), NULL)->element;
mjsBody* attached_body_1 = mjs_asBody(mjs_attach(frame, body, "attached-", "-1"));

或者 将刚体或 mjSpec 挂接到 site：

or attach a body or an mjSpec to a site:
mjSpec* parent = mj_makeSpec();
mjSpec* child = mj_makeSpec();
mjsElement* site = mjs_addSite(mjs_findBody(parent, "world"), NULL)->element;
mjsElement* body = mjs_addBody(mjs_findBody(child, "world"), NULL)->element;
mjsBody* attached_body_2 = mjs_asBody(mjs_attach(site, body, "attached-", "-2"));

或者 将坐标系或 mjSpec 挂接到刚体：

or attach a frame or an mjSpec to a body:
mjSpec* parent = mj_makeSpec();
mjSpec* child = mj_makeSpec();
mjsElement* body = mjs_addBody(mjs_findBody(parent, "world"), NULL)->element;
mjsElement* frame = mjs_addFrame(mjs_findBody(child, "world"), NULL)->element;
mjsFrame* attached_frame = mjs_asFrame(mjs_attach(body, frame, "attached-", "-1"));

请注意，在上面的示例中，父模型和子模型的 compiler.degree 取值不同，它对应 compiler/angle 属性，用于指定角度的解释单位。编译器标志在挂接时会被保留，因此子模型将使用子级的标志编译，而父模型将使用父级的标志编译。

Note that in the above examples, the parent and child models have different values for compiler.degree, corresponding to the compiler/angle attribute, specifying the units in which angles are interpreted. Compiler flags are carried over during attachment, so the child model will be compiled using the child flags, while the parent will be compiled using the parent flags.

还请注意，一旦子级以引用方式挂接到父级，该子级就不能再单独编译，也不能再整体挂接一次。其中尚未挂接的刚体和坐标系可以被挂接，前提是它们不包含任何已挂接的内容。父级的元素（包括以引用方式挂接到它上面的元素）只能以副本的形式挂接到该父级，参见 mjs_setDeepCopy。

Note also that once a child is attached by reference to a parent, the child cannot be compiled on its own or attached again as a whole. Its bodies and frames which are not attached yet can be attached, if they contain nothing which is attached already. An element of the parent, including one attached to it by reference, can be attached to the parent only as a copy, see mjs_setDeepCopy.

已知问题

Known issues

目前存在以下已知限制：

The following known limitations exist:

  • 如果父级和子级不是同一个 mjSpec，则子模型的所有资产都会被复制进来，无论它们是否被引用。

    All assets from the child model will be copied in, whether they are referenced or not, if the parent and the child are not the same mjSpec.

  • 以引用方式多次挂接的子级，会在第一次挂接时将其资产移到父级。后续挂接的元素只有在前缀和后缀相同时才能找到这些资产。

    A child attached by reference more than once moves its assets to the parent with the first attachment. The elements of a later attachment find them only if it has the same prefix and suffix.

  • 不会检查循环引用，循环引用会导致无限循环。

    Circular references are not checked for and will lead to infinite loops.

  • 挂接带有 关键帧 的模型时，其关键帧会立即添加到父级，但它们的向量以及父级自身关键帧的向量，只会在下一次编译时才为合并后的模型组装好。在此之前它们为空。

    When attaching a model with keyframes, its keyframes are added to the parent right away, but their vectors, and those of the keyframes of the parent, are assembled for the combined model only by the next compilation. Until then they are empty.

属性合并#

Attribute Merging

使用 mjs_attach 将子 spec（或子 spec 中的某个元素）挂接到父 spec 时，子级的全局属性可能与父级的冲突。当父级和子级都为同一字段指定了作者设定值且这些值不同时，就会发生冲突。请注意，对于基于 XML 的模型，显式写出某个值（即使它与默认值相同）也算作作者设定，并可能触发冲突。compiler/conflict 属性控制如何解决此类冲突。只有一方指定了作者设定值的字段永远不会冲突。

When attaching a child spec (or an element from a child spec) to a parent spec using mjs_attach, global attributes from the child may conflict with those in the parent. A conflict occurs when both the parent and child specify authored values for the same field and those values differ. Note that for XML-based models, explicitly writing a value (even if it matches the default value) counts as authoring and can trigger conflicts. The compiler/conflict attribute controls how such conflicts are resolved. Fields where only one side specifies an authored value never conflict.
warning （默认）
warning (default)

父级的值优先。每当检测到冲突，就会发出警告，但不会修改父级的值。这保持了原有的挂接行为。

Parent values take precedence. Whenever a conflict is detected, a warning is emitted but the parent value is not modified. This preserves the pre-existing attachment behavior.
merge

属性值按照下表所述的逐字段策略合并。当只有子级指定了作者设定值时，该值会被父级采用。

Attribute values are merged using a per-field strategy as described in the table below. When only the child specifies an authored value, it is adopted by the parent.
error

任何冲突都会导致编译错误。不会修改任何值。

Any conflict results in a compile error. No values are modified.

默认类#

Default classes

新 API 完全支持默认类，不过使用它们需要理解默认值是如何实现的。如 默认设置 一节所述，默认类首先被加载为一棵虚拟元素树，然后用于初始化引用它们的元素。在编辑带有默认值的模型时，这种初始化是显式的：

Default classes are fully supported in the new API, however using them requires an understanding of how defaults are implemented. As explained in the Default settings section, default classes are first loaded as a tree of dummy elements, which are then used to initialize elements which reference them. When editing models with defaults, this initialization is explicit:
mjSpec* spec = mj_makeSpec();
mjsDefault* main = mjs_getSpecDefault(spec);
main->geom.type = mjGEOM_BOX;
mjsGeom* geom = mjs_addGeom(mjs_findBody(spec, "world"), main);

需要注意的是，在默认类已被用于初始化元素之后再更改它，不会改变已初始化元素的属性。

Importantly, changing a default class after it has been used to initialize elements will not change the properties of already initialized elements.

未来可能的变更

Possible future change

上面描述的行为，即默认值只在初始化时应用，是旧的、仅基于 XML 的加载流水线的遗留物。未来的 API 变更可能允许在初始化之后更改并应用默认值。如果您认为该功能对您很重要，请在 GitHub 上告诉我们。

The behavior described above, where defaults are only applied at initialization, is a remnant of the old, XML-only loading pipeline. A future API change could allow defaults to be changed and applied after initialization. If you think this feature is important to you, please let us know on GitHub.

就地重新编译#

In-place recompilation

可以随时使用 mj_compile 进行编译，以获得新的 mjModel 实例。相比之下，mj_recompile 会就地更新现有的 mjModel 和 mjData 对，同时保留仿真状态。这使得模型编辑可以在 仿真期间 进行，例如添加或移除刚体。

Compilation with mj_compile can be called at any point to obtain a new mjModel instance. In contrast, mj_recompile updates an existing mjModel and mjData pair in-place, while preserving the simulation state. This allows model editing to occur during simulation, for example adding or removing bodies.
