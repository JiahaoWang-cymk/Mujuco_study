## 8.1 官方 notebook 做了什么

资料包里有官方的 LQR 教程：`../官方仓库_模型与教程/python/LQR.ipynb`（Jupyter 格式，用 VS Code 或 Jupyter 打开；文本编辑器里看到的是 JSON）。它让 MuJoCo 自带的 humanoid 单腿站住，分六步：

| 步 | notebook 里做的事 | 用到的函数 |
|---|---|---|
| ① | 取关键帧 1：单腿站立的姿势 | `mj_resetDataKeyframe` |
| ② | 把整个人上下挪 ±1 mm，找“竖直魔法力”最小的高度 | `mj_inverse` |
| ③ | 把平衡所需的关节力矩换算成控制量 `ctrl0` | 力臂矩阵的伪逆 |
| ④ | 设计代价矩阵 Q（质心对准支撑脚 + 关节别乱动）和 R | `mj_jacSubtreeCom`、`mj_jacBodyCom` |
| ⑤ | 在平衡点线性化，得到 A、B | `mjd_transitionFD` |
| ⑥ | 解 Riccati 方程得到增益 K，控制律 `ctrl = ctrl0 - K·dx` | `scipy.linalg.solve_discrete_are` |

搬到 G1 上，有四处不一样：

| | notebook 的 humanoid | G1 |
|---|---|---|
| 单腿姿势 | 模型自带关键帧 | 没有，要自己摆（8.3） |
| 执行器 | `motor`：`ctrl` 乘 gear 就是力矩 | `position`：`ctrl` 是**目标角度**（8.5） |
| 脚 | 胶囊体，脚掌大 | 4 个半径 5 mm 的小球，宽约 6 cm |
| Riccati 求解 | scipy | 只用 numpy 自己迭代（8.7） |

最要紧的是第二行。下面会看到，它让“平衡”这件事在 G1 上的样子完全不同。

## 8.3 第一步：摆出“左脚独立”

G1 的模型只有一个 `stand` 关键帧，单腿姿势要自己摆。思路和第 7 课的逆运动学一样，只是任务换了：

- **手工给定**：右腿抬起（髋 pitch −0.5、膝 1.0、踝 pitch −0.4），左腿微屈，两臂稍微张开。
- **让求解器决定**：骨盆的 6 个自由度、左腿 6 个关节、腰 roll 和 pitch，一共 14 个量。
- **要满足的任务**（按权重从大到小）：
  1. 左脚原地不动、脚底放平（6 维）；
  2. 整机质心的水平投影落在左脚中点（2 维，权重 ×3）；
  3. 躯干尽量竖直（2 维，权重 ×0.3）；
  4. 再加一点正则，让各关节别离手工值太远。

左脚中点怎么定？第 1 课讲过，每只脚 4 个小球的 x 坐标是 −0.05 和 0.12，中点比脚踝的 `left_foot` site 靠前 3.5 cm。

核心循环（完整代码见 `code/08_lqr_balance.py` 第 1 部分）：

```python
for _ in range(200):                                  # 阻尼最小二乘，反复迭代
    mujoco.mj_forward(m, d)
    mujoco.mj_jacSite(m, d, jp, jr, sL)               # 左脚 site 的位置、转动雅可比
    mujoco.mj_jacSubtreeCom(m, d, jc, PELVIS)         # 整机质心的雅可比
    mujoco.mj_jacBody(m, d, None, jt, TORSO)          # 躯干的转动雅可比
    J = np.vstack([jp, jr, 3 * jc[:2], 0.3 * jt[:2]]) * mask   # mask：只让 14 个量参与
    e = np.concatenate([foot_target - d.site_xpos[sL], rot_err(d.site_xmat[sL]),
                        3 * (com_target - d.subtree_com[PELVIS][:2]),
                        0.3 * rot_err(d.xmat[TORSO])[:2]])
    back = np.zeros(nv)
    mujoco.mj_differentiatePos(m, back, 1, d.qpos, qref)    # 指回手工姿势的方向
    dq = np.linalg.solve(J.T @ J + np.diag(reg) + 1e-6 * np.eye(nv), J.T @ e + reg * back)
    mujoco.mj_integratePos(m, d.qpos, dq, 1)          # 带四元数的 qpos 要用它来“加”
```

两个细节：

- `qpos` 里有四元数，不能直接 `qpos += dq`。“减”用 `mj_differentiatePos`，“加”用 `mj_integratePos`，第 1 课说过 nq ≠ nv 就是这个原因。
- `mj_jacSubtreeCom(m, d, jc, PELVIS)` 给的是骨盆**子树**的质心雅可比。骨盆是整棵树的根，所以就是整机质心。

运行结果：

质心离脚边最近只有 2.2 cm。单腿站立的难处就在这里：左右方向上，脚掌只有 5～6 cm 宽。

## 8.4 第二步：找平衡点

### notebook 的技巧：高度扫描

`mj_inverse` 的问题是：“要让机器人在这个姿势下**完全不动**（`qacc = 0`），各个自由度上需要多大的力？”关节上的力由电机出；骨盆 6 维没有电机，只能靠地面接触力。如果接触力解释不了，`qfrc_inverse[0:6]` 就不为 0，这部分是“魔法力”，现实里没人提供。

MuJoCo 的接触是软的，接触力取决于脚陷进地面多深。摆姿势时脚的高度是随手定的，陷得太深或太浅，竖直方向就需要很大的魔法力。notebook 的做法是：把整个机器人上下挪一挪，挑竖直魔法力最小的高度。

```python
offsets = np.linspace(-0.003, 0.003, 3001)                 # ±3 mm，步长 2 μm
for i, off in enumerate(offsets):
    q = q_pose.copy()
    q[2] += off                                            # 只改骨盆高度
    fz[i] = inverse(q)[2]                                  # inverse()：设 qvel=qacc=0 后调 mj_inverse
best = np.argmin(np.abs(fz))
```

```text
体重 327.1 N；最佳高度偏移 +1.488 mm，此时竖直魔法力 -0.435 N
只调高度后，骨盆 6 维魔法力 [fx fy fz mx my mz] = [ 0.     0.    -0.435 -3.475  2.541  0.237]
```

运行后打开 `output/08_lqr_balance.png`，左图就是这条曲线。往下压（负偏移），需要很大的向下魔法力把它“按”在地里；往上抬到 1.9 mm 附近，脚离开地面，需要的力正好等于体重 327 N，之后就不再变化。

### 只调高度够不够？

竖直力解决了，但还剩绕 x、y 轴的魔法力矩：−3.475 N·m 和 2.541 N·m。notebook 的 humanoid 也有这个问题（用 `code/08_notebook_humanoid.py` 可以看到，它的 mx 是 −3.447 N·m），只是那边无所谓，反正不加反馈它马上就倒。

G1 不一样。下一节会看到，这几 N·m 就决定了它不加反馈能不能站住。所以我们多做一步：把**高度、侧倾、前倾**三个量一起调，让 fz、mx、my 三个魔法力全部归零。三个方程三个未知数，用牛顿迭代，雅可比用有限差分算：

```python
ROOT_DOFS = [2, 3, 4]                     # qvel 里：z 平移、绕 x 转、绕 y 转
for it in range(6):
    r = inverse(qpos0)[ROOT_DOFS]
    for j, k in enumerate(ROOT_DOFS):     # 每个量挪 1e-6，看魔法力怎么变
        ...
        J[:, j] = (inverse(q)[ROOT_DOFS] - r) / 1e-6
    step[ROOT_DOFS] = np.linalg.solve(J, -r)
    mujoco.mj_integratePos(m, qpos0, step, 1)
```

```text
再调倾角后，骨盆 6 维魔法力 = [ 0.  0. -0.  0.  0.  0.]
  调整量：高度 +0.064 mm，侧倾 +0.292°，前倾 -0.018°
  平衡点处，质心到左脚支撑多边形边缘的最小距离 1.86 cm
  left_hip_roll_joint       需要  +34.17 N·m，占上限 24.6%
  left_ankle_pitch_joint    需要  +10.80 N·m，占上限 21.6%
```

只侧倾了 0.3°，魔法力就全没了。代价是质心到脚边的余量从 2.2 cm 降到 1.86 cm：整机绕骨盆转了一点，脚和质心转动的半径不一样，两者在水平方向上就错开了几毫米。所需力矩最大的是左髋 roll，34 N·m，用掉上限的四分之一。单腿时整个上身的重量都压在这一侧髋上，要靠它把骨盆“托平”。

## 8.5 position 执行器：和 notebook 最大的不同

### ctrl0 怎么求

notebook 的 humanoid 用 `motor` 执行器：力 = gear × ctrl。已知要的力矩，乘上力臂矩阵的伪逆就得到 `ctrl0`。

G1 用 `position` 执行器。第 2 课讲过它的力公式，写成 MuJoCo 的通用形式是

$$\text{force} = \underbrace{k_p}_{\texttt{gainprm[0]}}\cdot\text{ctrl} + \underbrace{0}_{\texttt{biasprm[0]}} \underbrace{-\,k_p}_{\texttt{biasprm[1]}}\cdot q \underbrace{-\,k_v}_{\texttt{biasprm[2]}}\cdot\dot q$$

静止时 $\dot q = 0$。要让它输出 $\tau_0$，就得

$$\text{ctrl}_0 = \frac{\tau_0 - \texttt{biasprm[0]} - \texttt{biasprm[1]}\cdot q}{\texttt{gainprm[0]}} = q + \frac{\tau_0}{k_p}$$

也就是说：**目标角要比实际角多偏一点，让“弹簧”拉出所需的力矩**。

```text
=== 3. 求 ctrl0 ===
代回检验：执行器力与 tau0 最大相差 5.26e-14 N·m
ctrl0 与关节角 q 最大相差 0.068 rad（left_hip_roll_joint）
左踝 roll：ctrl0 = +0.196，ctrlrange = [-0.262, +0.262]，离最近的限位 0.066 rad
```

左髋 roll 要多偏 0.068 rad（34.17 / 500）。左踝 roll 的 `ctrl0` 是 +0.196，离上限只剩 0.066 rad。G1 用了 `inheritrange="1"`，`ctrlrange` 就等于关节范围，超出的 ctrl 会被截断。也就是说，左踝 roll 往这个方向最多只能再“加” $500 \times 0.066 \approx 33$ N·m。这是 position 执行器特有的限制：**ctrl 的范围就是力矩的余量**。

### 不加反馈，会怎样

```text
=== 4. 不加反馈会怎样（每种最多跑 10 s）===
  A. ctrl = 关节角（只有 PD，不补偿重力）：1.30 s 失败
  B. ctrl = 只调高度的平衡点（notebook 做法）：1.67 s 失败
  C. ctrl = ctrl0（高度 + 倾角都调准）：10 s 都站住了
```

（“失败”指骨盆低于 0.5 m，或者除左脚以外有任何部位碰到地面。）

- **A**：目标角等于当前角，执行器一开始不出力，各关节在重力下先“塌”一点，才攒出力矩。塌的这一下让质心跑出了脚掌。
- **B**：那 3 N·m 的魔法力矩没人提供，整机会慢慢往右（左脚的内侧）滚，翻过脚边就倒了。
- **C**：平衡点算准了，**不加任何反馈也能单腿站 10 s**。

C 和 notebook 的结论正好相反。notebook 的 humanoid 只给 `ctrl0` 一定会倒，G1 却站住了。原因就在执行器上：

- motor 只出恒定的力矩，关节偏了也不会“拉回来”。整个人像一串软绳，站在一个点上，一碰就倒。
- position 执行器在每个关节上都装了一根 kp=500 的弹簧。G1 被这些弹簧撑成了一座“雕像”。雕像底座是平的，质心又在底座里面，小扰动下它自己就是稳的。

### 线性化：A 和 B 的含义变了

`mjd_transitionFD` 用有限差分算出离散时间的线性模型

$$\delta x_{t+1} = A\,\delta x_t + B\,\delta u_t,\qquad x = \begin{bmatrix}\delta q\\ \dot q\end{bmatrix}\ (2n_v = 70\ \text{维}),\quad u = \text{ctrl}\ (29\ \text{维})$$

```python
mujoco.mj_resetData(m, d)
d.qpos[:] = qpos0
d.ctrl[:] = ctrl0
A = np.zeros((2 * nv, 2 * nv))
B = np.zeros((2 * nv, nu))
mujoco.mjd_transitionFD(m, d, 1e-6, True, A, B, None, None)   # eps=1e-6，中心差分
```

```text
=== 5. 线性化 ===
A: (70, 70)，B: (70, 29)；A 的最大特征值模 1.000000，模 > 1.0001 的有 0 个
B 的含义：left_knee_joint 目标角 +1 rad，一步（2 ms）后它的角速度变化 1.09 rad/s
B 的含义：right_knee_joint 目标角 +1 rad，一步（2 ms）后它的角速度变化 1.69 rad/s
```

对照 `code/08_notebook_humanoid.py` 的输出：

```text
humanoid：nu=21，执行器类型 gaintype=0（0 = fixed，即 motor），gear=40，时间步长 5 ms
最佳高度偏移 -0.507 mm，骨盆 6 维魔法力 [ 0.     0.    -0.191 -3.447  0.222 -0.817]
只给 ctrl0、不加反馈：躯干起始高度 1.22 m，0.84 s 时已下降 0.2 m
A 的最大特征值模 1.0562，模 > 1.0001 的有 9 个（不稳定方向）
B 的含义：左膝 ctrl +1（= 80 N·m），一步后左膝角速度变化 1.61 rad/s
```

离散系统里，特征值的模大于 1，就表示这个方向的偏差会一步步放大。humanoid 有 9 个这样的方向，G1 一个也没有。这和上面“雕像”的说法一致。

把差别归纳一下：

| | motor（notebook） | position（G1） |
|---|---|---|
| `ctrl` 的单位 | 力矩 / gear | 目标角，rad |
| A 里有什么 | 只有机器人本身的动力学 | 机器人 **+ 每个关节的 PD 伺服**（$-k_p q$、$-k_v \dot q$ 都在 A 里） |
| B 的一列 | 这个电机多出 gear N·m，下一步状态怎么变 | 这个关节目标角多偏 1 rad（≈ 多出 500 N·m），下一步状态怎么变 |
| LQR 算出的 `-K·dx` | 力矩修正 | **目标角修正**：在内层 PD 之上再套一层外环 |
| R 的单位 | (ctrl)²，ctrl = 力矩 / gear | rad² |
| 饱和 | `forcerange`、`ctrlrange` | `ctrlrange` = 关节范围，`forcerange` 照样起作用 |

所以，G1 的 LQR 不直接出力矩，而是**每一步改一改各关节的目标角**。内层的 PD 伺服仍然在 MuJoCo 里以 500 Hz 跑着，LQR 看到的“被控对象”已经是“机器人 + 伺服”这个整体了。`mjd_transitionFD` 是对整个 `mj_step` 做差分，这件事它自动就处理好了；官方文档还说明，它对控制量的截断也做了正确处理。

> 既然不加反馈也能站，还要 LQR 做什么？雕像只扛得住小扰动。推一下，质心离开平衡位置，雕像只会僵着，等质心出了脚边就整个翻倒。LQR 会主动调整踝、髋、腰甚至手臂，把质心拉回来。8.8 节用推力测试来量化这一点。

## 8.6 第三步：Q、R，以及三个“漂移方向”

### Q 和 R 照搬 notebook

```python
mujoco.mj_jacSubtreeCom(m, d, jac_com, PELVIS)          # 整机质心
mujoco.mj_jacBodyCom(m, d, jac_foot, None, LFOOT)       # 左脚（left_ankle_roll_link）的质心
jac_diff = jac_com - jac_foot
Q_balance = jac_diff.T @ jac_diff                       # 质心相对左脚的偏移，平方

BALANCE_COST, BALANCE_JOINT_COST, OTHER_JOINT_COST = 1000, 3, 0.3   # 与 notebook 相同
Q_joint = np.eye(nv)
Q_joint[:6, :6] = 0                                     # 骨盆 6 维不直接惩罚
Q_joint[balance_dofs, balance_dofs] *= BALANCE_JOINT_COST   # 左腿 6 个 + 腰 roll/pitch
Q_joint[other_dofs, other_dofs] *= OTHER_JOINT_COST         # 其余：手臂、右腿、腰 yaw
Q[:nv, :nv] = BALANCE_COST * Q_balance + Q_joint        # 速度不直接惩罚
R = np.eye(nu)                                          # 单位：rad²
```

思路和 notebook 一样：

- **质心对准支撑脚**是头等大事，系数 1000。
- **支撑腿和腰**要稳，系数 3。
- **手臂、抬起的右腿**可以多动，系数 0.3，让它们去“甩”来帮忙平衡。

### 漂移方向：一个 notebook 没讲的坑

照搬后直接解 Riccati 方程，会发现迭代**不收敛**（后面有对照）。原因藏在 A 里。

找出所有满足 $A x = x$ 的方向，也就是“一步以后原样不变”的状态：

```python
_, sv, Vt = np.linalg.svd(A - np.eye(2 * nv))
drift = Vt[sv < 1e-6].T                                    # 每一列是一个漂移方向
```

```text
A - I 最小的 4 个奇异值 [0.    0.    0.    0.002]，于是有 3 个“漂移方向”：
  主要成分：qvel 下标 5（-0.982）、1（+0.156）
  主要成分：qvel 下标 0（-1.000）、35（-0.000）
  主要成分：qvel 下标 1（+0.988）、5（+0.155）
漂移方向上的代价 x'Qx：投影前最大 1.3e-01，投影后最大 5.3e-15
```

对照第 1 课的表，qvel 下标 0、1 是骨盆的 x、y 平移，5 是绕竖直轴转。这三个方向就是**整机在地上平移、整机原地转向**。

- 把整个机器人连脚一起挪 1 cm，它照样站着，没有任何力会把它拉回原处。所以理论上特征值正好是 1（有限差分算出来的是“非常接近 1”）。
- 关节怎么动也改变不了“整机在哪”。地面摩擦只阻止它滑动，并不把它往回推，所以这三个方向**不可控**。

LQR 的代价是把未来每一步的 $x^\top Q x$ 加起来。如果 Q 在漂移方向上有一点点权重（这里是 0.13，来自 `Q_balance` 对转向的依赖），而这个偏差又永远消不掉，代价就会一直累加到无穷，Riccati 方程也就没有有限解。

> notebook 为什么没碰到这个问题？它用的是 scipy。有限差分算出的 A，特征值只是“非常接近 1”，并不精确等于 1，所以 scipy 照样能算出一个 P，只是这个 P 被漂移方向撑得非常大（8.7 节的打印：大了 116 倍）。“能算出数”不等于“算对了”。

解决办法：告诉 Q“别管这三个方向”，把它投影到漂移方向的补空间：

```python
Pi = np.eye(2 * nv) - drift @ drift.T
Q = Pi @ Q_raw @ Pi
```

这不影响平衡。我们关心的是质心相对脚的位置，而不是机器人站在地板的哪一块。

## 8.7 第四步：只用 numpy 解 Riccati 方程

notebook 里的两个公式（离散时间 LQR）：

$$P = Q + A^\top P A - A^\top P B\,(R + B^\top P B)^{-1} B^\top P A$$

$$K = (R + B^\top P B)^{-1} B^\top P A$$

notebook 直接调 `scipy.linalg.solve_discrete_are`。第 0 课装的环境里没有 scipy，我们就自己解。最直接的办法是**不动点迭代**：从 $P = Q$ 出发，把右边算出来当成新的 P，反复代入，直到 P 不再变化。

```python
def riccati_iterate(A, B, Q, R, tol=1e-10, max_iter=20000):
    """最朴素的不动点迭代：把 notebook 里的 Riccati 方程反复代入，直到 P 不再变化。"""
    P = Q.copy()
    for k in range(1, max_iter + 1):
        BtP = B.T @ P
        K = np.linalg.solve(R + BtP @ B, BtP @ A)
        P_new = Q + A.T @ P @ (A - B @ K)       # 与上面的公式等价，少算一次求逆
        P_new = 0.5 * (P_new + P_new.T)         # 保持对称，抑制舍入误差
        change = np.max(np.abs(P_new - P)) / np.max(np.abs(P_new))
        P = P_new
        if change < tol:
            return P, k, change
    return P, max_iter, change
```

这个迭代有直观含义：迭代 N 次得到的 P，就是“只往前看 N 步”的最优代价。N 越大越接近无限时域，收敛后就是 LQR 的解。

```text
=== 6. 解 Riccati 方程 ===
朴素迭代：682 次收敛，用时 0.07 s，方程相对残差 9.6e-11
倍增迭代：12 次收敛，用时 0.003 s，与朴素迭代的 K 相对差 1.5e-08
（装了 scipy，核对一下：与 solve_discrete_are 的 P 相对差 1.2e-06）
（scipy 对不投影的 Q 也会给出一个 P，但 max|P| 是投影后的 116 倍）
对照：不做投影，朴素迭代 3000 次后 P 每步仍变化 4.3e-08（收敛判据 1e-10）
K: (29, 70)；闭环 A-BK 最大的几个特征值模 [1.    1.    1.    0.991 0.985]
K 中左踝 roll 一行的最大元素 18.65
```

- 朴素迭代 682 次收敛，不到 0.1 s（用时和电脑有关，下同）。
- 脚本里还有一个**倍增迭代**（`riccati_doubling`）：每迭代一次，相当于朴素迭代的“往前看的步数”翻一倍，所以 12 次就够了。两者的 K 相差 1.5e-8。状态维数再大几倍时，它的优势会很明显。
- 如果你的环境里恰好装了 scipy，脚本会顺便核对一下，没装就跳过这两行。
- 不做 8.6 的投影，3000 次后 P 还在每步涨一点。漂移方向的代价每一步都要再加一份，所以它会一直涨下去，实际上到不了收敛判据。
- 闭环 $A - BK$ 的特征值：三个 1 是漂移方向（LQR 管不了，也不需要管），其余都小于 1。


“质心到脚边”是从平衡点的质心出发，沿推力方向走到支撑多边形边上的距离（脚的内侧边略斜，所以不是简单地拿 y 坐标相减）。

1. **按 10 N 一档量，四个方向 LQR 都是不加反馈的 2 倍。** 档位很粗，“2 倍”只是个大概，不要当成什么定律。
2. **左右比前后弱得多。** 脚长 17 cm，宽只有 5～6 cm。往右推最弱，因为质心离脚的内侧边只有 1.9 cm。
3. **LQR 已经接近“倒立摆极限”。** 最后一列是粗估：把机器人看成一根倒立摆，质量 M，质心高 h。推一下给它冲量 I，质心获得速度 v = I/M。倒立摆有个“捕获点”：质心带着速度 v，还会再往前冲 v/ω 才可能停住，其中 $\omega = \sqrt{g/h}$。这段距离不能超过脚边 d，所以

$$I_{\max} \approx M\,\omega\,d$$

例如向前：$33.34 \times 3.753 \times 0.086 \approx 10.8$ N·s。LQR 扛住的 100 N × 0.1 s = 10 N·s，已经到了极限的九成多；左右两个方向是 4.0/4.5、2.0/2.3，也都在八九成。这个估计只考虑“脚不动、靠踝调整”。想扛得更多，就要甩手臂、扭髋（髋策略），甚至跨一步，后者已经超出“围着一个平衡点做线性化”的 LQR 的能力。

## 如果报错

| 现象 | 可能原因 | 解决 |
|---|---|---|
| `WARNING: Nan, Inf or huge value in QACC ... The simulation is unstable` | 推力太大，或者改的姿势、增益让仿真发散了 | 脚本的 `survive()` 会检查 `d.warning[mjWARN_BADQACC]`，直接判为失败。自己写循环时也要检查：MuJoCo 发散后会**自动重置** `MjData`，`d.time` 回到 0，`while d.time < T` 会一直跑下去 |
| 朴素迭代跑满 20000 次还没收敛 | Q 在不可控的漂移方向上有权重 | 确认做了 8.6 的投影；改姿势后漂移方向的个数可能变化，看打印的奇异值 |
| `RuntimeError: 倍增迭代没有收敛` | 同上，或 A、B 里出现了 NaN | 同上；检查 `mjd_transitionFD` 前是否设好了 `qpos0` 和 `ctrl0` |
| 改了姿势以后，不加反馈的 C 方案也倒 | 质心离脚边太近，或 `ctrl0` 被 `ctrlrange` 截断了 | 看第 1 部分打印的“最小距离”和第 3 部分的“离最近的限位”；让质心更靠近脚的中心 |
| 魔法力矩调不到 0，牛顿迭代发散 | 姿势里脚没放平，只有一两个小球着地 | 检查第 1 部分的逆运动学是否收敛；看 `d.ncon` 是否为 4 |
| 图里的中文是方框 | 系统里没有微软雅黑或黑体 | 改 `plt.rcParams["font.sans-serif"]`，换成系统里有的中文字体；不影响计算结果 |
| `--view` 窗口打不开 | 远程桌面或虚拟机的图形驱动问题 | 先不加 `--view` 运行，看打印结果和 `output/` 里的图；第 10 课会讲怎么离屏录视频 |
