.. _UI:

用户界面
--------

.. note::
   :class: mt-notice

   本页由 AI（Claude Sonnet）根据 MuJoCo 官方英文文档（2026-11-16 版）翻译，仅供学习参考；如有出入，以英文原版为准。术语对照见资料包中的 ``术语表.md`` 。

MuJoCo 拥有原生的 UI 框架，其用法在 :ref:`simulate.cc <saSimulate>` 查看器中有所演示。该框架被设计为在更新和渲染方面速度快，对开发者和用户都易于使用，
跨平台，并且与 MuJoCo 原生渲染器集成。为了实现这些设计目标，我们省略了其他 UI 框架中提供的许多功能和自定义选项，转而专注于效率和自动化。



.. _uiDesign:

设计概览
~~~~~~~~


原生 OpenGL 渲染
  我们不使用任何辅助工具或库，而是提供 C 代码，直接用 OpenGL 渲染所有 UI 元素。我们支持多个 UI，每个 UI 都是一个虚拟矩形，其高度可以超过可见窗口。
  每个 UI 的元素通过最小化更新、仅在必要时被渲染（rendering）到离屏的辅助 OpenGL 缓冲区中。在每次屏幕刷新时，我们再把这些辅助缓冲区中的像素复制到窗口帧缓冲区，
  并且当窗口小于 UI 时还实现了垂直滚动条。该复制操作在 GPU 上完成，速度非常快。


平台抽象
  软件设计分为 3 层：与 MuJoCo 渲染器（完全跨平台）协同工作的 UI 元素 OpenGL 渲染；用于访问窗口、键盘和鼠标的抽象函数，它们在 ``PlatformUIAdapter``
  类中被定义为纯虚函数；以及这些函数在派生类 ``GlfwAdapter`` 中的实现。\ `GLFW <https://www.glfw.org/>`__ 本身是跨平台的。尽管如此，我们仍选择这种分层设计，
  以便将通用功能与平台相关功能分离。如果出于某种原因需要用另一个类似的框架替换 GLFW，则只需重写 ``GlfwAdapter``。


主题与外观
  单个 UI 元素不允许在外观或布局方面进行自定义。相反，我们使用主题来设定颜色和间距，并自动排列所有 UI 元素。系统提供了若干内置主题，用户也可以设计
  自定义主题，不过整个 UI 的所有元素使用同一个主题。外观极简：主要是带文字的彩色矩形。不支持位图和其他自定义装饰。UI 元素的类型有复选框、
  单选按钮组、选择列表、滑块、文本编辑框、静态文本、按钮、分隔符。这些元素被组织成可以展开和折叠的分区。


布局与矩形
  每个 UI 都是一个虚拟矩形，其宽度由主题决定，高度则由各分区、每个分区内的条目以及各分区的展开/折叠状态决定。这些虚拟矩形的尺寸和辅助缓冲区在 UI 更新时自动处理。
  每个 UI 在屏幕上有一个可见矩形，此外还有其他矩形——用于 3D 渲染、2D 图形，以及可能的自定义 OpenGL
  渲染。所有这些可见矩形都保存在 :ref:`mjuiState` 中，并用于确定鼠标事件应被分派到何处。矩形布局由用户提供的回调函数更新。


静态分配与创建
  我们并不分配和释放大量与 UI 元素对应的对象并将它们相互链接，而是创建单个 C 结构体（类型为 :ref:`mjUI`），以静态分配的方式支持一定数量上限的
  分区和元素，然后记录当前使用了多少个。UI 的创建借助辅助函数得以简化，这些函数的输入是一个 C 结构体（类型为 :ref:`mjuiDef`），它本质上是一张表，其中每一行描述一个 UI 元素
  （见下文）。这使得只需出人意料地少量 C 代码就能构建复杂的用户界面。也可以通过编程方式创建 UI，例如用与 MuJoCo 模型（model）关节（joint）对应的滑块来填充 UI。


最小状态
  UI 被设计为尽可能无状态，以简化开发。这有两个方面。首先，我们不在 UI 元素内部复制用户数据，而是存储指向用户数据的指针。例如，我们可以创建一个 UI
  滑块，并将其数据指针设为 ``mjData* d->qpos+7``。该滑块将可视化并控制 MuJoCo 模型 qpos 向量的第 7 个标量
  分量。因此，当仿真更新时，我们必须记得同时更新 UI。此外，在仿真更新期间我们还必须禁用 UI 编辑。但其优点是
  UI 更易于构建，并且不会出现用户数据与 UI 不一致的风险。
  其次，UI 元素本身大多是无状态的。我们转而跟踪一组最小的全局状态，特别是
  鼠标和键盘状态、分区的展开/折叠状态，以及正在编辑的文本框的内容（如果有的话）。


自动启用与禁用
  虽然每个 UI 条目都可以直接设置为启用或禁用状态，但我们也提供如下自动化机制。每个 UI
  条目可以被分配一个整数类别。然后由 :ref:`mjfItemEnable` 回调函数根据某些程序特定的条件决定每个类别应被启用还是
  禁用。例如，可以改变 MuJoCo 模型关节取值的滑块，在仿真状态更新期间应被禁用。
