=====
类型
=====

.. note::
   :class: mt-notice

   本页由 AI（Claude Sonnet）根据 MuJoCo 官方英文文档（2026-11-16 版）翻译，仅供学习参考；如有出入，以英文原版为准。术语对照见资料包中的 ``术语表.md`` 。

MuJoCo 定义了大量类型：

- 四种\ :ref:`基本类型<tyPrimitive>`\ ：\ :ref:`mjtNum<mjtNum>`、\ :ref:`mjtByte<mjtByte>`、\ :ref:`mjtBool<mjtBool>` 和
  :ref:`mjtSize<mjtSize>`。

- 用于定义分类取值的 :ref:`C 枚举类型<tyEnums>`。这些类型可分为：

  - 用于 :ref:`mjModel<tyModelEnums>` 的枚举。
  - 用于 :ref:`mjData<tyDataEnums>` 的枚举。
  - 用于抽象\ :ref:`可视化<tyVisEnums>`\ （visualization）的枚举。
  - 供\ :ref:`经典渲染器<tyRenderEnums>`\ 使用的枚举。
  - 供 :ref:`filament 渲染器<tyFilamentRenderEnums>`\ 使用的枚举。
  - 供 :ref:`mjUI<tyUIEnums>` 用户界面包使用的枚举。
  - 供\ :ref:`引擎插件<tyPluginEnums>`\ 使用的枚举。
  - 用于\ :ref:`过程式模型操作<tySpecEnums>`\ 的枚举。

  请注意，API 并不直接使用这些枚举类型，而是使用 int，并由文档和注释说明某些 int 对应于某些枚举类型。这是因为我们希望 API 与编译器无关，而 C
  标准并未规定表示一个枚举类型必须使用多少字节。尽管如此，为了提高可读性，我们建议在调用以枚举类型为参数的 API 函数时使用这些类型。

- :ref:`C 结构体类型<tyStructure>`。这些类型可分为：

  - 主要结构体：

    - :ref:`mjModel`。
    - :ref:`mjOption`\ （嵌入在 :ref:`mjModel` 中）。
    - :ref:`mjData`。

  - :ref:`辅助结构体类型<tyAuxStructure>`，同样被引擎使用。
  - 用于收集\ :ref:`仿真统计信息<tyStatStructure>`\ 的结构体。
  - 用于\ :ref:`抽象可视化<tyVisStructure>`\ 的结构体。
  - 供\ :ref:`经典渲染器<tyRenderStructure>`\ 使用的结构体。
  - 供 :ref:`filament 渲染器<tyFilamentRenderStructure>`\ 使用的结构体。
  - 供 :ref:`UI 框架<tyUIStructure>`\ 使用的结构体。
  - 用于\ :ref:`过程式模型操作<tySpecStructure>`\ 的结构体。
  - 供\ :ref:`引擎插件<tyPluginStructure>`\ 使用的结构体。

- 若干用于用户自定义回调的\ :ref:`函数类型<tyFunction>`。
- 关于需要详细说明的特定数据结构的\ :ref:`tyNotes`。



.. _tyPrimitive:

基本类型
--------

以下三种类型定义在 `mjtype.h <https://github.com/google-deepmind/mujoco/blob/main/include/mujoco/mjtype.h>`__ 中。


.. _mjtNum:

mjtNum
^^^^^^

这是整个仿真器中使用的浮点类型。在默认构建配置下，\ ``mjtNum`` 被定义为 ``double``。如果定义了符号 ``mjUSESINGLE``，则 ``mjtNum`` 被定义为
``float``。

目前只发布双精度版本的 MuJoCo，尽管整个代码库同样可以在单精度下工作。我们将来可能会发布单精度版本，但双精度版本将始终可用。因此，假定双精度来编写用户代码是安全的。不过，我们更倾向于编写既能在单精度下工作、也能在双精度下工作的代码。为此，我们提供了始终以正确浮点类型定义的数学工具函数。

请注意，修改 ``mjtype.h`` 中的 ``mjUSESINGLE`` 并不会改变库的编译方式，反而会导致大量链接错误。一般来说，用户绝不应修改随预编译 MuJoCo 一同发布的头文件。

.. code-block:: C

   // floating point data type and minval
   #ifndef mjUSESINGLE
     typedef double mjtNum;
     #define mjMINVAL    1E-15       // minimum value in any denominator
   #else
     typedef float mjtNum;
     #define mjMINVAL    1E-15f
   #endif


.. _mjtByte:

mjtByte
^^^^^^^

用于表示小整数和二进制数据的字节类型。

.. code-block:: C

   typedef unsigned char mjtByte;


.. _mjtBool:

mjtBool
^^^^^^^

用于表示真/假值的布尔类型。

.. code-block:: C

   #ifndef __cplusplus
     typedef _Bool mjtBool;
   #else
     typedef bool mjtBool;
   #endif


.. _mjtSize:

mjtSize
^^^^^^^

用于表示缓冲区大小的尺寸类型。

.. code-block:: C

   typedef int64_t mjtSize;

.. _mjtDisableBit:

mjtDisableBit
~~~~~~~~~~~~~

2 的幂常量。它们用作 :ref:`mjOption` 的字段 ``disableflags`` 的位掩码。运行时该字段为 ``m->opt.disableflags``。这些常量的个数由
``mjNDISABLE`` 给出，它同时也是全局字符串数组 :ref:`mjDISABLESTRING` 的长度，该数组包含这些标志的文字描述。

.. mujoco-include:: mjtDisableBit


.. _mjtEnableBit:

mjtEnableBit
~~~~~~~~~~~~

2 的幂常量。它们用作 :ref:`mjOption` 的字段 ``enableflags`` 的位掩码。运行时该字段为 ``m->opt.enableflags``。这些常量的个数由
``mjNENABLE`` 给出，它同时也是全局字符串数组 :ref:`mjENABLESTRING` 的长度，该数组包含这些标志的文字描述。

.. mujoco-include:: mjtEnableBit


.. _mjtJoint:

mjtJoint
~~~~~~~~

基本关节（joint）类型。这些值用于 ``m->jnt_type``。注释中的数字表示每种关节类型拥有多少个位置坐标。请注意，球关节以及自由关节的旋转部分以单位四元数（quaternion）表示，它们各有
4 个位置坐标，但只有 3 个自由度（degree of freedom）。

.. mujoco-include:: mjtJoint


.. _mjtGeom:

mjtGeom
~~~~~~~

MuJoCo 支持的几何类型。第一组是可以在模型中使用的“正式”geom 类型。第二组是不能在模型中使用、但被可视化器用来添加装饰元素的 geom 类型。这些值用于 ``m->geom_type`` 和
``m->site_type``。

.. mujoco-include:: mjtGeom


.. _mjtProjection:

mjtProjection
~~~~~~~~~~~~~

相机投影的类型。用于 ``m->cam_projection``。

.. mujoco-include:: mjtProjection


.. _mjtCamLight:

mjtCamLight

.. mujoco-include:: mjtCamLight


.. _mjtLightType:

mjtLightType

.. mujoco-include:: mjtLightType

.. mujoco-include:: mjtTextureRole

.. mujoco-include:: mjtLogLevel


.. _mjtLogTopic:

mjtLogTopic
"""""""""""

信息类消息的主题标识符。与 :ref:`mju_info` 配合用于基于主题的过滤。主题 0（``mjTOPIC_NONE``）始终通过默认处理程序的过滤器。其他主题必须在 :ref:`mjLogConfig` 位掩码中启用。由于主题从 1 开始编号，主题 ``t`` 的位掩码为
``(1 << (t - 1))``。可过滤主题的数量由 ``mjNTOPIC`` 给出，它同时也是字符串数组 :ref:`mjTOPICSTRING` 的长度。

.. mujoco-include:: mjtLogTopic

.. _tyFilamentRenderStructure:

Filament 渲染
^^^^^^^^^^^^^^^^^^

这些结构体类型的名称以 ``mjrf`` 为前缀。它们定义在
`mjrfilament.h <https://github.com/google-deepmind/mujoco/blob/main/include/mujoco/mjrfilament.h>`__ 中。

该 API 定义了七种关键类型： :ref:`mjrfContext<mjrfContext>` 、 :ref:`mjrfTexture<mjrfTexture>` 、
:ref:`mjrfMesh<mjrfMesh>` 、 :ref:`mjrfLight<mjrfLight>` 、 :ref:`mjrfRenderable<mjrfRenderable>` 、
:ref:`mjrfScene<mjrfScene>` 和 :ref:`mjrfRenderTarget<mjrfRenderTarget>` 。

每个对象都通过 `create` 函数创建，并通过 `destroy` 函数销毁，例如 `mjrf_createTexture` 和
`mjrf_destroyTexture` 。除 :ref:`Context<mjrfContext>` 对象自身外，创建所有对象都需要一个 :ref:`Context<mjrfContext>` 。此外， `create` 函数接受一个指向配置结构体（例如 `mjrTextureConfig` ）的指针，该结构体描述待创建对象的参数。每个这样的结构体都有对应的 `default` 函数（例如 `mjrf_defaultTextureConfig` ），可用于将结构体初始化为默认值。除非另有说明，默认值均视为 `0` 或 `NULL` 。


.. _mjrfContext:

mjrfContext
~~~~~~~~~~~

Context 是 filament 渲染库的主入口。它管理负责渲染图像的所有 filament 核心对象。所有其他对象（例如 Texture、Mesh、Scene 等）都需要一个 Context 才能创建。

除此之外，与 Context 配合使用的主要函数是 :ref:`mjrf_render()<mjrf_render>` ，它负责实际渲染图像。

Filament 使用单独的线程进行渲染。尽管如此，该 API 并不是线程安全的；调用应当在单个线程中发起。由于 filament 具有异步特性，部分 API 会提供句柄或回调，用于在操作完成时发出信号。（注意：对于 WASM 构建，filament 不使用单独的线程。）

:ref:`mjrfContext<mjrfContext>` 与经典的 :ref:`mjrContext<mjrContext>` 有两点关键区别。首先，filament 上下文会自行管理底层的图形上下文，这意味着用户无需事先初始化 EGL 或类似的库。其次，filament 上下文独立于 MuJoCo 模型，这意味着可以用单个 :ref:`mjrfContext<mjrfContext>` 实例为多个模型渲染图像。

.. _mjrfMesh:

mjrfMesh
~~~~~~~~

网格（mesh）描述待渲染对象的表面几何。它由一组顶点（即 VertexBuffer）、一组描述顶点处理顺序的索引（即 IndexBuffer），以及一个图元类型组成；图元类型定义了渲染表面时顶点应如何被解释（例如三角形、线段等）。

Filament 并不直接支持法线。它会把法线、切线和副切线编码为一个 4 分量四元数（quaternion），用来描述顶点的“朝向”。理想情况下，应当对资产进行预处理，离线生成这些数据；不过如有需要，我们会即时计算（但会带来性能开销）。

顶点数据可以交错存放，也可以不交错。交错数据假定各属性按照 attributes 数组中指定的顺序紧密排列，中间没有填充。此外，每个属性的 `data` 指针被假定指向该类型的第一个元素。对于非交错数据，则假定每个属性存放在各自独立的数组中。

此外，应当计算网格的包围范围，以便 filament 渲染器执行基于视锥体的剔除。或者，也可以在运行时计算包围范围（但会有少量性能开销）。如果没有提供（或计算）包围范围，则不会执行视锥体剔除。

.. _mjrfLight:

mjrfLight
~~~~~~~~~

光源是照明的来源。（没有光源，渲染出的图像将是一片漆黑。）光源有多种类型，例如平行光、聚光灯、点光源和图像光源。

场景中的主光源是图像光源（有时也称为环境光）。这种光源“包围”整个场景，并被定义为一张 3D 纹理。立方体贴图的每个“像素”被解释为从特定方向投射到场景中的颜色。

用于基于图像照明的纹理可以使用 filament 的 `cmgen` 工具生成。应将该工具配置为从源图像输出 KTX 文件。该工具会计算额外的数据（即球谐函数），并将这些信息编码到 KTX 文件中。

平行光是下一种最常见的光源，通常用于模拟太阳：即沿单一方向发射的、颜色均匀的光。

Filament 仅支持单个图像光源和单个平行光。点光源和聚光灯则可以定义任意多个。除基于图像的光源外，每个光源都可以选择是否投射阴影。每个投射阴影的光源都会带来性能开销。

.. _mjrfMaterial:

mjrfMaterial
~~~~~~~~~~~~

材质描述 renderable 表面的属性，实际上决定了表面如何与光源相互作用，从而在输出图像中产生最终的像素颜色。根据材质属性取值的不同，表面将应用不同的光照模型。目前支持三种光照模型：

1. Metallic-roughness（PBR）：这是基于标准金属度-粗糙度工作流渲染模型时的首选模型。

2. Specular-glossiness（非 PBR）：这是一种旧式模型，旨在与经典的 :ref:`mjr<ClassicRendering>` 渲染器兼容，但并非 100% 相同。

3. Unlit：该模型忽略光照，用于渲染 UX 或装饰性元素，例如接触力和标签。

.. _mjsFlex:

mjsFlex
~~~~~~~

柔性体规格（Flex specification）。

实验性的整数 ``elastic3d`` 用于为非插值的 3D 柔性体选择材料： ``0`` （默认值）为 Saint Venant-Kirchhoff（StVK）弹性，
``1`` 为简化的 Stable Neo-Hookean（SNH）弹性。其他取值会被拒绝。
SNH 需要 :ref:`离散积分器<option-integrator>` 。该设置只能通过 :ref:`mjSpec` 使用，没有对应的 MJCF 属性。启用了 SNH 的规格无法保存为 MJCF；编译后的模型可以保存为 MJB。
SNH 会先将每个单元的材料 Hessian 投影到半正定，再将其映射到顶点坐标。
离散求解器和 Rayleigh 阻尼复用这一投影后的算子。能量和弹性力保持不变，仍通过求逆来定义。材料阻尼的瞬时功率非正，但投影并不保证无翻转（inversion-free）运动，也不保证在任意时间步长下的稳定性。

.. mujoco-include:: mjsFlex

注记
-----

本节包含关于 MuJoCo 结构体类型中数据结构约定的各种注记。


.. _tyNotesCom:

c 坐标系变量
^^^^^^^^^^^^^^^^^

:ref:`mjData` 包含两个带 ``c`` 前缀的数组，用于内部计算： ``cdof`` 和
``cinert`` ，二者均由 :ref:`mj_comPos` 计算。 ``c`` 前缀表示这些量是相对于“c 坐标系”（frame）的，
即原点位于局部运动学子树质心（ ``mjData.subtree_com`` ）、姿态与世界坐标系一致的坐标系。
这一选择提高了远离全局原点的机构的运动学计算精度。

``cdof``:
  这些 6D 运动向量（3 个转动、3 个平移）描述自由度（degree of freedom）的瞬时轴线，
  被所有雅可比（Jacobian）函数使用。计算解析雅可比所需的最小计算是先执行 :ref:`mj_kinematics` ，
  再执行 :ref:`mj_comPos` 。

``cinert``:
  这些 10 维向量描述刚体在 c 坐标系中的惯性属性，被复合刚体算法（Composite Rigid Body）
  （ :ref:`mj_crb` ）使用。这 10 个数是长度为 (6, 3, 1) 的打包数组，语义如下：

  ``cinert[0-5]``: 刚体惯性矩阵（inertia matrix）的上三角部分。

  ``cinert[6-8]``: 刚体质量乘以刚体质心相对于 c 坐标系原点的偏移。

  ``cinert[9]``: 刚体质量。

.. _tyNotesConvex:

凸包
^^^^^^^^^^^^

凸包描述符存储在 :ref:`mjModel` 中：

.. code-block:: C

   int*      mesh_graphadr;     // graph data address; -1: no graph      (nmesh x 1)
   int*      mesh_graph;        // convex graph data                     (nmeshgraph x 1)

如果网格（mesh） ``N`` 在 :ref:`mjModel` 中存有凸包（这是可选的），则 ``m->mesh_graphadr[N]`` 是网格 ``N`` 的凸包数据
在 ``m->mesh_graph`` 中的偏移量。每个网格的凸包数据是一条记录，格式如下：

.. code-block:: C

   int numvert;
   int numface;
   int vert_edgeadr[numvert];
   int vert_globalid[numvert];
   int edge_localid[numvert+3*numface];
   int face_globalid[3*numface];

注意，凸包包含的是完整网格顶点的一个子集。我们用 ``globalid`` 这一命名表示完整网格中的顶点索引，用 ``localid`` 表示凸包中的顶点索引。
各字段的含义如下：

``numvert``
   凸包中的顶点数。

``numface``
   凸包中的面数。

``vert_edgeadr[numvert]``
   对凸包中的每个顶点，这是该顶点的边记录在 edge_localid 中的偏移量。

``vert_globalid[numvert]``
   对凸包中的每个顶点，这是它在完整网格中对应的顶点索引

``edge_localid[numvert+3*numface]``
   它包含一系列边记录，凸包中的每个顶点对应一条。每条边记录是一个以 -1 结尾的顶点索引数组（采用 localid 格式）。
   例如，假设顶点 7 的记录为：3, 4, 5, 9, -1。
   这表示顶点 7 属于 4 条边，这些边的另一端分别是顶点 3, 4, 5, 9。这样，
   每条边都被表示两次，分别位于其两个顶点的边记录中。注意，对于封闭的三角形网格
   （例如这里使用的凸包），边数为 ``3*numface/2`` 。因此，当每条边被表示两次时，共有 ``3*numface edges`` 。
   并且由于我们在每条边记录末尾使用分隔符 -1（每个顶点一个分隔符）， ``edge_localid`` 的长度为 ``numvert+3*numface`` 。

``face_globalid[3*numface]``
   对凸包的每个面，它包含该面三个顶点在完整网格中的索引
