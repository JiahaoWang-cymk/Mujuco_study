.. _saTestspeed:

`testspeed <https://github.com/google-deepmind/mujoco/blob/main/sample/testspeed.cc>`_
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

该代码示例对给定模型的仿真进行计时。计时方式很直接：对被动动力学（可选地加入控制噪声）按指定的步数进行展开，同时从内部性能分析中收集接触数量、标量约束数量和 CPU 时间的统计信息，然后将结果打印到控制台。如果要仿真受控动力学而非被动动力学，可以安装控制回调 :ref:`mjcb_control`，或者按照下文\ :ref:`仿真循环 <siSimulation>`\ 一节的说明修改代码以显式设置控制信号。这个命令行工具的运行方式为

.. code-block:: Shell

   testspeed [options] model

其中命令行选项和参数为

.. list-table::
   :width: 95%
   :align: left
   :widths: 2 1 4
   :header-rows: 1

   * - 选项
     - 默认值
     - 含义
   * - ``model``
     - （必需）
     - 模型路径（位置参数）
   * - ``--nstep=N``
     - 10000
     - 每次展开的步数
   * - ``--nthread=N``
     - 1
     - 并行展开所用的线程数
   * - ``--noisestd=X``
     - 0.01
     - 注入执行器的伪随机噪声的尺度
   * - ``--noiserate=X``
     - 0.1
     - 向 ctrl 关键帧/中点收敛的速率
   * - ``--nenginethread=N``
     - 0
     - 引擎内部线程池中的工作线程数
   * - ``--solver=S``
     - Newton
     - 覆盖约束求解器算法（PGS、CG、Newton）
   * - ``--cone=C``
     - Pyramidal
     - 覆盖摩擦锥类型（Pyramidal、Elliptic）
   * - ``--jacobian=J``
     - Auto
     - 覆盖约束雅可比矩阵类型（Dense、Sparse、Auto）
   * - ``--integrator=I``
     - Euler
     - 覆盖积分模式（Euler、RK4、Implicit、ImplicitFast）
   * - ``--iterations=N``
     - 100
     - 覆盖求解器迭代次数上限
   * - ``--tolerance=X``
     - 1e-8
     - 覆盖求解器收敛容差
   * - ``--sleep_tolerance=X``
     - 1e-4
     - 覆盖休眠容差
   * - ``--noslip_iterations=N``
     - 0
     - 覆盖 noslip 求解器迭代次数上限

**注意事项：**

- 当指定 ``nthread > 1`` 时，代码会分配一个 mjModel 和每个线程各自的 mjData，并并行运行 ``nthread`` 个相同的仿真。这会在所有核心都处于活动状态的情况下测试性能，如同在并行收集样本的强化学习场景中一样。最优的 ``nthread`` 通常等于逻辑核心数。
- 默认情况下，仿真从模型的参考构型（reference configuration）以零速度开始。但是，如果模型中存在名为 "test" 的关键帧（keyframe），则以该关键帧作为初始状态。
- 物理选项覆盖标志（如 ``--solver``）只有在命令行中被显式指定时才会覆盖模型设置；否则，保留 XML 文件中配置的模型选项。
- 控制噪声参数（``noisestd`` 和 ``noiserate``）可以防止模型稳定到静止状态；在静止状态下，由于热启动（warmstart），测得的仿真速度会被人为地加快。
- 当指定 ``nenginethread > 0`` 时，会创建一个包含指定数量工作线程（不含调用线程）的引擎内部线程池，用于加速大型场景的仿真。请注意，虽然可以同时使用 ``nthread`` 和 ``nenginethread``，但需要这两种不同多线程方式的场景通常是互斥的。
- 为了获得更可重复的性能统计数据，请在 Linux 上以 ``performance`` `调速器 <https://www.kernel.org/doc/Documentation/cpu-freq/governors.txt>`__\ （governor）运行该工具，或在 Windows 上使用 ``High Performance`` 电源计划，以减少 CPU 频率缩放带来的噪声。
- 许多现代 CPU 同时包含“性能”核心和“能效”核心。用户应考虑将进程限制在同一类型的核心上运行，以获得更易于解释的性能统计数据。这可以在 Linux 上通过 `taskset <https://man7.org/linux/man-pages/man1/taskset.1.html>`__ 命令完成，或在 Windows 上通过 `start /affinity <https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/start>`__ 命令完成（在 macOS 上无法通过有文档记录的 API 方式指定处理器亲和性）。

.. _saSimulate:

`simulate <https://github.com/google-deepmind/mujoco/blob/main/simulate>`_
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

该代码示例是一个功能完备的交互式仿真器。它使用与平台无关的 GLFW 库打开一个 OpenGL 窗口，并在其中渲染仿真状态。它带有内置帮助、仿真统计信息、性能分析器和传感器（sensor）数据曲线。模型文件可以作为命令行参数指定，也可以在运行时通过拖放加载。该代码示例使用原生 UI 来渲染各种控件，并展示了新 UI 框架的预期用法。下面是 ``simulate`` 运行时的屏幕录像：

代码很长，但注释相当充分，因此最好直接阅读。这里我们给出一个高层概述。\ ``main()`` 函数初始化 MuJoCo 和 GLFW，打开一个窗口，并安装用于处理鼠标和键盘的 GLFW 回调。请注意这里没有渲染回调；GLFW 把控制权交给用户，而不是在幕后运行渲染循环。主循环处理 UI 事件和渲染。仿真在后台线程中处理，并与主线程同步。

鼠标和键盘回调执行所需的各种操作。其中许多操作调用了 MuJoCo 的\ :ref:`抽象可视化 <Abstract>`\ 机制所提供的功能。实际上，该机制的设计目的就是或多或少直接挂接到鼠标和键盘事件上，并提供相机以及扰动控制。

性能分析器和传感器数据曲线展示了 :ref:`mjr_figure` 函数的用法，该函数可以绘制带有网格、标注、坐标轴缩放等功能的复杂二维图形。性能分析器中显示的信息提取自 mjData 的诊断字段。它是调节约束求解器算法参数的非常有用的工具。模型中定义的传感器的输出以条形图的形式显示。

请注意，性能分析器显示的是用高分辨率计时器收集的计时信息。在 Windows 上，根据电源设置，操作系统可能会降低 CPU 频率；这是因为 :ref:`simulate.cc <saSimulate>` 大部分时间处于休眠状态，以便减慢到实时速度。这会导致计时不准确。要避免这个问题，请更改 Windows 电源计划，使最小处理器状态为 100%。

.. _saCompile:

`compile <https://github.com/google-deepmind/mujoco/blob/main/sample/compile.cc>`_
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

该代码示例调用内置的解析器和编译器。它实现了从（MJCF、URDF、MJB）格式到（MJCF、MJB、TXT）格式的所有可能的模型转换。模型按照\ :ref:`模型编码与保存 <meSaving>`\ 所述的方式保存为 MJCF：默认情况下，保存的是编译后得到的值，采用格式的规范子集，因此 MJCF 到 MJCF 的转换通常会得到不同的文件；当 :ref:`savecompiled<compiler-savecompiled>` 为 "false" 时，则按原样写出，这会保留其记法，但不保留注释、\ :ref:`include<include>` 元素以及被解析器展开的元素。TXT 格式是模型的一份人类可读的路线图。它不能被 MuJoCo 加载，但在模型开发期间可以是非常有用的辅助。它与编译后的 mjModel 一一对应。另请注意，可以使用函数 :ref:`mj_printData` 创建与 mjData 一一对应的文本文件，不过该代码示例并未这样做。

如果输入文件是 MJCF 或 URDF 且输出文件为空，则会执行两次编译，以衡量编译器\ :ref:`资源缓存<Assetcache>`\ 的影响。每次编译都会打印详细的计时明细，显示总时间、资源处理时间（挂钟时间）以及网格和纹理各类别的 CPU 时间。这些计时数据通过 :ref:`mjs_getTimer` 从 :ref:`mjtCTimer` 字段中读取，在任何一次 :ref:`mj_compile` 调用之后都可以通过编程方式读取。

.. _saBasic:

`basic <https://github.com/google-deepmind/mujoco/blob/main/sample/basic.cc>`_
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

该代码示例是一个最小化的交互式仿真器。模型文件必须作为命令行参数提供。它使用与平台无关的 GLFW 库打开一个 OpenGL 窗口，以 60 fps 渲染仿真状态，同时以实时速度推进仿真。按 Backspace 可重置仿真。可以用鼠标控制相机：左键拖动旋转，右键拖动在垂直平面内平移，Shift 加右键拖动在水平平面内平移，滚轮或中键拖动缩放。

下文的 :ref:`Visualization` 编程指南解释了可视化的工作原理。该代码示例是对该指南中各概念的最小化演示。

.. _saRender:

`render <https://github.com/google-deepmind/mujoco/blob/main/sample/render.cc>`_
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

该代码示例将模型离屏渲染为单张 PNG 图像，或渲染为多帧原始 RGB24 帧流；该帧流可以保存为 ``.rgb`` 文件，或直接通过管道传给 ``ffmpeg`` 等工具。它既支持采用基于物理的渲染（PBR）的现代 Filament 渲染后端（:ref:`mjrf <FilamentRenderingApi>`），也支持经典的 OpenGL 渲染器（:ref:`mjrContext`），并且以无头方式运行，无需创建交互式窗口。

.. code-block:: Shell

   render model [output] [options]

其中命令行参数和选项为

.. list-table::
   :width: 95%
   :align: left
   :widths: 2 1 4
   :header-rows: 1

   * - 选项
     - 默认值
     - 含义
   * - ``model``
     - （必需）

   * - ``output``
     - （默认）

       ``<model>.rgb``）
   * - ``--backend=B``
     - ``filament``
     - 渲染后端（``filament``、\ ``classic``）
   * - ``--width=N``

   * - ``--height=N``

   * - ``--duration=T``

   * - ``--camera=C``

   * - ``--lookat=X,Y,Z``
     - （中心）

   * - ``--distance=D``

     - 自由相机的距离
   * - ``--azimuth=A``
     - ``90``
     - 自由相机的方位角（度）
   * - ``--elevation=E``
     - ``-45``
     - 自由相机的仰角（度）
   * - ``--key=K``
     - （无）

   * - ``--steps=N``

     - ``111000``
     - 用 6 个字符的字符串启用/禁用 geom 组 0-5（例如 ``111111``）
   * - ``--sitegroup=S``

     - 用 6 个字符的字符串启用/禁用 site 组 0-5
   * - ``--label=L``
     - （无）

   * - ``--frame=F``

     - （默认）

   * - ``--<rndflag>=0|1``

例如，可以将每秒 60 帧、时长 5 秒的视频直接通过管道传给 ``ffmpeg``，而无需将原始帧写入磁盘：

.. code-block:: Shell

   render humanoid.xml - --duration=5 --fps=60 --width=1280 --height=720 | \
     ffmpeg -f rawvideo -pixel_format rgb24 -video_size 1280x720 -framerate 60 \
            -i - -pix_fmt yuv420p video.mp4

**注意事项：**

- 不带参数（或带 ``--help`` / ``-h``）运行 ``render`` 会打印帮助信息。
- 必需的 ``model`` 路径和可选的 ``output`` 路径都是位置参数。如果省略 ``output``，则输出文件名由模型文件名派生：单帧渲染（``--duration=0``）使用 ``.png``，多帧录制（``--duration > 0``）使用 ``.rgb``。将 ``-`` 作为 ``output`` 传入时，会把原始 RGB24 帧流式输出到标准输出，并将状态消息发送到标准错误。
- ``--backend=filament`` 和 ``--backend=classic`` 都输出自上而下的 RGB24 帧（第 0 行在顶部），因此 ``ffmpeg`` 不需要 ``vflip`` 滤镜。
- ``--backend=filament`` 使用 MuJoCo 的 Filament C API 根据模型配置场景，设置光照、材质和纹理，并通过 Filament 的离屏管线进行渲染。\ ``--backend=classic`` 使用标准的 OpenGL 离屏渲染。
- 默认相机是模型的自由相机，注视场景中心。指定 ``--camera=name`` 会选择模型 XML 中定义的命名相机，而整数索引 ``0, 1, ...`` 则按定义顺序选择固定相机。使用自由相机时，可以通过 ``--lookat=x,y,z``、\ ``--distance=d``、\ ``--azimuth=a`` 和 ``--elevation=e`` 调整其视点。
- 如果通过 ``--key`` 指定了关键帧，则在计算运动学并渲染之前，模型状态会被重置为该关键帧。如果未指定关键帧，且模型中存在名为 ``test`` 的关键帧，则默认使用它。
- ``--steps=N`` 会在渲染或开始 ``--duration`` 录制之前（在任何关键帧重置之后）将仿真推进 ``N`` 步，因此可以直接捕获通过仿真到达的某个状态或片段。
- 可以使用 :ref:`mjVISSTRING` 和 :ref:`mjRNDSTRING` 中的规范化标志名称单独切换可视化和渲染标志。
- 可以使用 ``--label=L`` 启用标签，其中 ``L`` 是 :ref:`mjLABELSTRING` 中的标签类型名称（例如 ``geom``、\ ``body``、\ ``joint``）或整数索引。
- 可以使用 ``--frame=F`` 渲染坐标系，其中 ``F`` 是 :ref:`mjFRAMESTRING` 中的坐标系类型名称（例如 ``geom``、\ ``body``、\ ``site``、\ ``world``）或整数索引。
