第 7 课　伸手碰球：雅可比与逆运动学

对应入门教程：4.7、8.1、9.1、9.4

本课目标

  • 用 MjSpec 给 G1 的右手加一个末端点（site），在场景里加一个目标小球（mocap body）。
  • 理解雅可比：关节转一点点，手会移动多少；会用 mj_jacSite 取出它。
  • 写一个阻尼最小二乘（DLS）逆运动学，只动右臂 7 个关节，把手送到球上。
  • 把 IK 结果交给位置伺服，让站着的 G1 真的伸手碰到球；理解为什么仿真里会差一点，以及怎样修正。
  • 看清 DLS 在“够不着”时的表现，体会阻尼的取舍；知道加上腰以后能够得更远，也更容易摔。
  • 用 contype / conaffinity 决定球是“幽灵”还是“实心”。

预计用时：2–2.5 小时　前置：第 2 课（stand 关键帧、position 执行器）、第 3 课（MjSpec 改模型）

7.1 要解决的问题：已知手的位置，反求关节角

前几课一直在做正运动学：给出 qpos，mj_kinematics 算出每个 body、每个 site 在哪里。这一步有唯一答案，算起来也快。

这一课反过来：球在 (0.30, -0.20, 1.00)，右臂 7 个关节各该转多少度，手才能碰到它？这叫逆运动学（IK）。它难在三点：

  • 没有现成公式。 7 个关节、带各种偏置的连杆，写不出解析解。
  • 解不唯一。 手的位置只有 3 个数，关节却有 7 个，多出来的 4 个自由度可以“随便摆”（比如手不动、手肘上下转）。
  • 可能无解。 球太远，手臂伸直了也够不着。

MuJoCo 不直接提供 IK 函数，但给了做数值 IK 需要的全部零件：正运动学、雅可比、关节范围。本课用它们自己拼一个。

7.2 用 MjSpec 加末端点和目标球

末端点放在哪

G1 的右手是 right_wrist_yaw_link 上的一块橡胶手（right_rubber_hand 网格）。脚本算了一下它的网格范围：在手腕坐标系里 x 方向大约从 0.04 m 延伸到 0.17 m。我们把末端点放在 x = 0.13 m，大致是手掌中部偏前。

为什么要专门加一个 site，而不直接用 body 的位置？body 的原点在手腕关节上，离手掌还有十几厘米。site 是“挂在 body 上、没有物理作用的坐标系标记”（第 1 课 1.3 ⑥），专门用来标记末端点、装传感器。

目标球为什么用 mocap body

球要满足两个要求：不能被重力拉掉，又要能随时挪到新位置。mocap body 正好如此：

  • 它是世界的直接子 body，不受任何力，不会掉也不会被推走。
  • 位置不写在 qpos 里，而写在 d.mocap_pos[k] 里，随时可以改，改了下一步就生效。
  • 下标 k 不是 body id，要用 m.body_mocapid[body_id] 换算。

代码

def build_model(ball_collides=False):
    spec = mujoco.MjSpec.from_file(str(XML))

    if ball_collides:
        ...                                    # 7.8 节再讲
    else:

        target.add_geom(name="ball", type=mujoco.mjtGeom.mjGEOM_SPHERE,

几点说明：

  • spec.body("right_wrist_yaw_link") 按名字找到要挂 site 的 body，和第 3 课的用法一样。原始的 g1.xml 一个字都没改，改动只存在于内存里的这份 spec 中。
  • G1 默认类里的 site 是 group="5"，查看器里默认看不到。这里显式写 group=0，绿色小点一开查看器就能看见。
  • 球半径 BALL_R = 0.04 m。默认情况下球是纯标记：contype=0、conaffinity=0，和什么都不碰撞（为什么这样选，7.8 节专门讲）。判断“碰到了”的标准是：手掌 site 进入球内，也就是 site 到球心的距离小于 40 mm。

运行后第一行会打印 nsite=5 ngeom=73 nmocap=1：原来 4 个 site 加 1 个，原来 72 个 geom 加 1 个球。机器人质量仍是 33.34 kg。

7.3 雅可比：关节动一点，手动多少

设手掌位置是 \(p\)（3 个数），全身速度是 \(\dot q\)（G1 有 nv = 35 个）。它们之间是线性关系：

\[\dot p = J_p\,\dot q,\qquad J_p \in \mathbb{R}^{3\times 35}\]

\(J_p\) 就是平移雅可比。第 \(i\) 列表示：只让第 \(i\) 个自由度以 1 rad/s（或 1 m/s）运动时，手掌的速度。

jacp = np.zeros((3, m.nv))                 # 必须是 3×nv、float64
mujoco.mj_kinematics(m, d)                 # 先更新位姿
mujoco.mj_comPos(m, d)                     # 雅可比要用到的中间量
mujoco.mj_jacSite(m, d, jacp, None, sid)   # 不要旋转雅可比，就传 None
J = jacp[:, vadr]                          # 只取右臂 7 个关节那几列 → 3×7
  • 第 4 个参数是旋转雅可比 jacr（手的角速度）。本课只管手到哪，不管手朝哪，所以传 None。
  • 35 列里大多数和右手无关：左臂、腿的列全是 0。要注意的是前 6 列（浮动基）和腰的 3 列不是 0：骨盆或腰一动，手当然跟着动。本课只取右臂 7 列，等于假设身体其余部分不动。7.5 节会看到这个假设在仿真里带来的后果。
  • vadr 是右臂 7 个关节在 qvel 里的下标，用 m.jnt_dofadr 取（第 1 课 1.5 的表里是 28–34）。

7.4 阻尼最小二乘：一步一步把手挪过去

思路很朴素：现在差 \(e = p_{\text{目标}} - p_{\text{当前}}\)，想找一个关节增量 \(\Delta q\) 让 \(J\,\Delta q \approx e\)。\(J\) 是 3×7 的“扁”矩阵，不能直接求逆。阻尼最小二乘（Damped Least Squares，DLS）解的是

\[\min_{\Delta q}\ \|J\,\Delta q - e\|^2 + \lambda^2\|\Delta q\|^2 \quad\Longrightarrow\quad \Delta q = J^\top\left(J J^\top + \lambda^2 I\right)^{-1} e\]

  • 第一项：手尽量往目标走。
  • 第二项：关节别动太多。\(\lambda\) 叫阻尼，入门教程 9.1 的例子里写的 1e-4 就是 \(\lambda^2\)（\(\lambda = 0.01\)）。
  • 只要 \(\lambda > 0\)，\(JJ^\top + \lambda^2 I\) 一定可逆，手臂伸直（奇异位形）时也不会除以零。

雅可比只在当前姿态附近准确，所以一步到不了，要迭代：算误差 → 算雅可比 → 走一小步 → 重来。

def solve_ik(m, d0, target, joints, damping=0.05, max_iter=200, tol=1e-4, max_step=0.2):
    d = mujoco.MjData(m)                       # 单独一份数据，只做运动学，不碰 d0
    d.qpos[:] = d0.qpos
    ...
    for it in range(max_iter + 1):             # 最多走 max_iter 步；多一轮只为量出最后一步之后的误差
        mujoco.mj_kinematics(m, d)
        mujoco.mj_comPos(m, d)
        err = target - d.site_xpos[sid]
        errs.append(np.linalg.norm(err))
        if errs[-1] < tol or it == max_iter:   # 误差小于 0.1 mm，或步数用完，就停
            break
        mujoco.mj_jacSite(m, d, jacp, None, sid)
        J = jacp[:, vadr]
        dq = J.T @ np.linalg.solve(J @ J.T + damping**2 * np.eye(3), err)
        s = np.abs(dq).max()                   # 一步太大就整体缩小，防止跳过头
        if s > max_step:
            dq *= max_step / s
        d.qpos[qadr] = np.clip(d.qpos[qadr] + dq, lo, hi)   # 不能超出关节范围
    return d.qpos[qadr].copy(), errs, steps

和入门教程 9.1 相比，多了三处工程上的处理：

  1. 单独一份 MjData。 IK 只是“在脑子里比划”，不能去动正在仿真的 d。新建的 d 从仿真里的当前状态出发，骨盆、腿、腰都在实际位置上。
  2. 单步限幅 max_step = 0.2 rad。 离目标很远时，线性近似很不准，一步迈太大容易越过头。7.7 节会看到它的作用。
  3. 按关节范围截断。 算出的角度超出 range，伺服也执行不了，不如在 IK 里就截掉。

另外注意循环跑的是 max_iter + 1 轮：最后一步走完后再量一次误差。这样返回的关节角和 errs 里最后一个误差对应同一个姿态。少了这一轮，打印的“末误差”其实是倒数第二个姿态的；7.7 节会看到，够不着时相邻两步的姿态可能差得很远。

入门教程用 mj_integratePos 更新 qpos，这样对球关节、自由关节也成立。这里 7 个关节都是铰链，qpos 和 qvel 一一对应，直接相加是对的。如果你把骨盆的 freejoint 也放进 IK，就必须改用 mj_integratePos。

7.5 把 IK 结果交给位置伺服

IK 给出的是 7 个目标角度。G1 的执行器正好是位置伺服（第 2 课），ctrl 就是目标角度，所以直接把结果写进 ctrl。只是不要一下子跳过去，否则手臂会猛甩一下，甚至把自己晃倒。脚本用 1 s 的 smoothstep 曲线（起点、终点速度都是 0）过渡，再保持 2 s：

s = min((d.time - t0) / ramp, 1.0)
s = 3 * s**2 - 2 * s**3
d.ctrl[aids] = c0 + s * (q_goal - c0)

四个目标点（世界坐标，G1 面朝 +x，右手在 −y 一侧）：

7.6 差的 12 mm 从哪来：开环与闭环

IK 是在“身体不动”的假设下算的。真实情况是：手臂伸出去，整机质心前移，腿和腰的伺服被压得稍微变形，身体会跟着晃一点；手臂自己也要扛重力，位置伺服 kp=500 不是无限硬（第 2 课）。

实验 2 把这两部分拆开算（只做运动学，不仿真）：

=== 实验 2：A 点，按实际状态再做 IK 修正 3 轮 ===
  开环：12.47 mm
  手臂关节跟踪误差 0.0044 rad → 单独造成 2.6 mm
  骨盆前移 5.7 mm、腿和腰最多转了 0.0066 rad → 单独造成 11.0 mm
  修正第 1 轮后：0.68 mm
  修正第 2 轮后：0.05 mm
  修正第 3 轮后：0.02 mm
  • 手臂关节最多只差了 0.0044 rad（约 0.25°），单独算只让手偏 2.6 mm。
  • 大头在身体：骨盆往前挪了 5.7 mm，腿和腰的关节转了不到 0.4°，但它们离手掌有一米远的“杠杆”，放大成 11 mm。

所以只靠给手臂加重力补偿（第 6 课的思路）解决不了主要矛盾。办法是闭环修正：手伸过去以后，从实际的身体状态出发再做一次 IK，看看还差多少关节角，把差值加到 ctrl 上。

q_need, _, _ = solve_ik(m, d, target, joints)      # d 是正在仿真的状态
goal = d.ctrl[aids] + (q_need - d.qpos[qadr])       # 还差多少，就在目标上多给多少

为什么不直接 ctrl = q_need？因为伺服有稳态误差：给 ctrl = q 它停在 q 附近，差 0.004 rad 左右。在当前 ctrl 上加上差值，等于把稳态误差也一并补掉。修正一轮就从 12.47 mm 降到 0.68 mm，三轮后 0.02 mm。

这就是“开环”和“闭环”的区别：开环是算好了一次性执行；闭环是边做边看结果、再修正。真实机器人上，“实际状态”来自关节编码器和 IMU 的状态估计；看球的位置则要靠相机。

7.7 够不着怎么办：阻尼的取舍

D 点离肩膀 0.811 m，IK 停在 297 mm 的误差上，说明右臂最多伸出约 0.811 − 0.297 ≈ 0.51 m（和实验 3 末尾直接扫肘角得到的 0.511 m 一致）。DLS 没有报错，也没有发散，只是尽量往球的方向伸。这是阻尼项的功劳：误差降不下去时，\(\lambda^2\|\Delta q\|^2\) 不让关节无止境地乱转。

但阻尼取多大合适？实验 3 用三个阻尼值分别解 A 和 D：

=== 实验 3：阻尼大小（A 能够到，D 够不着） ===
    阻尼 | A 迭代次数 | D 末误差(mm) | D 最后 20 步最大步长(rad)
   0.001 |         10 |        298.8 | 0.2000   （D 的肘角 +1.277）
    0.05 |         10 |        296.8 | 0.2000   （D 的肘角 +1.315）
     0.3 |         27 |        296.0 | 0.0018   （D 的肘角 +1.405）

看最后一列：

  • 阻尼 0.001 和 0.05 时，D 点到第 200 次迭代，每步关节还在动 0.2 rad，正好是限幅的上限。它没有停下，而是在两个姿态之间来回跳。把 max_iter 依次设成 195、196……200 分别求解，打印结果可以看到：阻尼 0.05 时肘角在 1.315 和 1.45 之间交替，手腕 pitch 在 −0.023 和 0.177 之间交替；阻尼 0.001 时肘角在 1.277 和 1.41 之间交替，末误差也跟着在 298.8 和 296.1 mm 之间跳。手臂接近伸直时 \(JJ^\top\) 有一个方向的奇异值很小，阻尼太小就压不住那个方向，算出的步长被限幅截到 0.2 rad，下一步又跳回来。
  • 阻尼 0.3 时，D 稳稳停下（最后每步只动 0.0018 rad），肘角 1.405，接近伸直。（G1 的肘角为 0 时小臂水平朝前、和大臂成直角。脚本在实验 3 末尾扫了一遍肘角：1.45 rad 时肩到手掌最远，0.511 m。）
  • 代价是：够得着的 A 点，阻尼 0.3 要 27 次迭代，阻尼 0.05 只要 10 次。阻尼越大，每一步越“保守”。

三种阻尼的末误差差不多（296–299 mm），但阻尼小时“停在哪一步就取哪一步”，交给伺服的目标会随机落在两个姿态之一。实际系统里常见的折中是自适应阻尼：离目标近时用小阻尼求快，误差降不下去时自动加大阻尼求稳。练习 2 还会看到，把限幅也去掉会更糟。

7.8 加上腰：够得更远，也更容易摔

把腰的 3 个关节（yaw、roll、pitch）也加进 IK，joints 从 7 个变成 10 个，代码一行不用改，雅可比自动多取 3 列。实验 4 选了一个“胳膊差一点”的 E 点：

=== 实验 4：右臂 7 + 腰 3 = 10 个关节 ===
  E 点 [ 0.55 -0.2   0.95]，离右肩 0.575 m
  只用手臂：200 次迭代，末误差 61.2 mm
  加上腰  ：9 次迭代，末误差 0.01 mm，腰 yaw/roll/pitch = [ 0.349 -0.104  0.259]
  仿真开环：44.0 mm；修正 3 轮：2.8 → 2.3 → 0.7 mm；骨盆高 0.791 m
  D 点加腰：IK 末误差 165.2 mm，腰 = [0.794 0.52  0.52 ]；仿真 3 s 后骨盆高 0.167 m
  • E 点只用手臂差 6 cm 够不着；加上腰，上身向左转 0.349 rad（yaw 绕 +z 轴，正值是从上往下看逆时针，正好把右肩往前送）、前倾 0.259 rad，9 次迭代就够到了。
  • 仿真里开环差 44 mm，比只动手臂时大得多：上身前倾，质心前移更多，腿被压得更厉害。修正 3 轮后降到 0.7 mm，骨盆高度 0.791 m，仍然站着。
  • D 点即使加上腰也差 165 mm（这里同样在两个姿态之间来回跳，换个 max_iter 会看到 192 mm 左右的另一个值）。IK 把腰 roll 和 pitch 都拉到了 0.52 rad 的关节极限。把这个结果交给伺服，3 s 后骨盆只有 0.167 m 高：G1 摔倒了。

IK 只管手到哪，不管站不站得住。 动到腰甚至腿以后，就必须同时考虑平衡：质心要留在两脚之间的支撑区域里（第 4 课）。专业的全身控制会把“手到目标”和“质心在支撑区内”写成多个任务，按优先级一起求解。第 8 课会用 LQR 处理平衡问题。

7.9 碰撞过滤：球是“幽灵”还是“实心”

到目前为止，球是个纯标记，contype=0、conaffinity=0，手可以穿进去。为什么不让它“实心”？入门教程 8.1 讲过，两个 geom 要检测碰撞，必须同时满足：

  1. 不在同一个 body 上；
  2. 两个 body 不是父子关系（父 body 是世界或静态时例外）；
  3. 位掩码匹配：(contype1 & conaffinity2) || (contype2 & conaffinity1) 不为 0；
  4. 没有被 <contact><exclude> 排除。

先看 G1 自己的情况：第 1 课讲过，visual 类的 geom 都是 contype="0" conaffinity="0"。橡胶手 right_rubber_hand 只用了 visual 类，手掌根本没有碰撞体。手腕上倒是有一个碰撞 mesh，但它在手腕坐标系里只到 x = 0.04 m，离手掌 site 还有 9 cm。

所以就算把球设成默认的 contype=1 conaffinity=1，手掌也会直接穿过它（练习 3 来验证）。要让手真的“摸”到球，得先给手掌补一个碰撞体。实验 5 这样做：

target.add_geom(name="ball", ..., contype=2, conaffinity=2)
hand.add_geom(name="palm_collision", type=mujoco.mjtGeom.mjGEOM_SPHERE,
              pos=PALM_POS, size=[PALM_R, 0, 0],
              contype=2, conaffinity=2, density=0, group=3)

为什么用 2 而不是 1？按位掩码算一遍：

geom 对 计算 结果
球 (2, 2) — 手掌球 (2, 2) 2 & 2 = 2 碰撞
手掌球 (2, 2) — 躯干、大腿等 (1, 1) 2 & 1 = 0，1 & 2 = 0 不碰
手掌球 (2, 2) — 地面 (1, 1) 同上 不碰
球 (2, 2) — 手腕碰撞 mesh (1, 1) 同上 不碰

用一个“专用的位”，就只开了“手掌—球”这一对，不会让新加的手掌球意外撞上自己的胸口或大腿。这比用 <contact><pair> 显式列出也更省事。另外 density=0 让手掌球不增加质量，group=3 让它和其他碰撞体一起显示和隐藏。

实验 5 让 IK 仍然瞄准球心，看会发生什么：

=== 实验 5：球和手掌碰撞球都设 contype=conaffinity=2 ===
  ball            contype=2  conaffinity=2
  palm_collision  contype=2  conaffinity=2
  floor           contype=1  conaffinity=1
  手腕碰撞 mesh       contype=1  conaffinity=1
  IK 仍瞄准球心，末误差 0.09 mm（IK 不知道有碰撞）
  仿真 3 s 末：手掌 site 到球心 59.5 mm（两球半径和 60 mm），接触 ['palm_collision-ball']，法向力 13.73 N
  • IK 只是在“脑子里”算，不知道有碰撞，仍然算出一个让手掌伸进球心的姿态。
  • 仿真里手被球挡住了：手掌 site 到球心 59.5 mm，正好约等于两个半径之和 60 mm（软接触允许约 0.5 mm 的穿透，见入门教程第 8 章开头）。
  • 伺服的目标在球里面，它一直“往里顶”，于是产生了 13.73 N 的接触力。mocap 球不会被推走，力全部传回到机器人身上。

怎么选？

做法 适合 注意
球不碰撞（本课默认） 只想验证 IK、可视化目标点 “碰到”要自己用距离判断
球和手掌都碰撞（实验 5） 想看接触力，或让手真的推、按、拍一个东西 IK 的目标要设在球的表面外侧，否则伺服会一直顶着
球是自由物体（加 freejoint） 想把球拍走、推倒 球会被碰飞；还要考虑摩擦（第 5 课）

练习

  1. 换左手。 把 site 改挂到 left_wrist_yaw_link，关节名里的 right 换成 left，四个目标点的 y 坐标取反。（solve_ik 和 reach 里按名字 "right_palm" 找 site：要么新 site 仍叫这个名字，要么把这两处一起改掉。）猜一猜：IK 迭代次数、7 个关节角，和右手的结果有什么关系？
  2. 去掉单步限幅。 调用 solve_ik 时传 max_step=1e9（相当于不限幅），分别用阻尼 0.001 和 0.05 解 D 点，记下末误差和最大步长。和实验 3 比，变好了还是变差了？
  3. “实心球”不一定挡得住手。 不补手掌碰撞球，只把球改成 contype=1, conaffinity=1（MuJoCo 的默认值），对 A 点做开环伸手。手会被挡住吗？用 d.contact 查一下有没有和球有关的接触。
  4. 给手臂加重力前馈（联系第 6 课）。 对 A 点，在 IK 结果的姿态上调用 mj_forward，读出右臂 7 个关节的 qfrc_bias，把 ctrl 设为 q_ik + qfrc_bias / kp（kp=500）。仿真里手到球心的距离从 12.5 mm 变成多少？和 7.6 节的误差分解对得上吗？
