第 4 课　它“感觉”到了什么

对应入门教程：3.3、3.5、5.7、7.2

本课目标

  • 读懂 G1 自带的两个 IMU：陀螺仪测什么，加速度计静止时为什么读到 +9.81。
  • 用 MjSpec 给模型补上关节传感器，并和 qpos、qvel、actuator_force 逐个对账。
  • 遍历 d.contact，算出左右脚各自承受多大的力，验证“脚底合力 = 体重”。
  • 算出整机质心和支撑多边形，判断质心投影在不在支撑区里；再推它一下，看所有读数怎么变。

预计用时：1.5–2 小时　前置：第 1 课（qpos/qvel 排布）、第 2 课（position 执行器、stand 关键帧）、第 3 课（MjSpec 入门）

4.1 本课要做的事

真机上的控制器看不到“上帝视角”的 qpos，它只能靠传感器知道自己的状态。机器人能用的信息主要有三类：

来源 是什么 仿真里怎么拿
惯性测量单元 IMU 陀螺仪 + 加速度计，模型在躯干和骨盆各装了一个 g1.xml 里已经定义好的 4 个传感器
关节编码器、电机电流 每个关节的角度、角速度、力矩 自己加 jointpos、jointvel、actuatorfrc 传感器，或直接读 MjData
足底力 很多人形机器人脚底没有力传感器，只能从关节力矩、IMU 间接估计 仿真里可以直接读接触力，当作“标准答案”

本课脚本 code/04_senses.py 分三段：

A. 站立 1 s 后，把所有“感觉”读一遍：IMU、关节、接触力、质心与支撑区
B. 把机器人抬高 1 m 让它自由下落 0.1 s，再读一次加速度计
C. 从 t = 1.0 s 起，往机器人左侧推躯干 30 N，持续 0.2 s，记录 3 s 内的全部读数并画图

运行：

python code/04_senses.py                    # 无界面，打印结果，图和 CSV 存到 output/
python code/04_senses.py --force 60         # 换一个推力（N）
python code/04_senses.py --dir backward     # 换个方向推：left / right / forward / backward
python code/04_senses.py --view             # 打开查看器实时看 C 段（显示接触力和质心）

每次运行都会覆盖 output/ 里的 04_senses.png、04_support.png、04_push_log.csv。想保留某次结果，先把文件改个名再换参数跑。

4.2 IMU：陀螺仪和加速度计

G1 的 g1.xml 末尾有这样一段：

<sensor>
  <gyro site="imu_in_torso" name="imu-torso-angular-velocity" cutoff="34.9" noise="0.0005"/>
  <accelerometer site="imu_in_torso" name="imu-torso-linear-acceleration" cutoff="157" noise="0.01"/>
  <gyro site="imu_in_pelvis" name="imu-pelvis-angular-velocity" cutoff="34.9" noise="0.0005"/>
  <accelerometer site="imu_in_pelvis" name="imu-pelvis-linear-acceleration" cutoff="157" noise="0.01"/>
</sensor>
  • gyro（陀螺仪）：site 坐标系下的角速度，单位 rad/s。
  • accelerometer（加速度计）：site 坐标系下的线加速度，单位 m/s²，包含重力的影响。
  • 两者都在 site 自己的坐标系里表示，不是世界坐标系。机器人歪了，读数的分量就跟着变。
  • cutoff：输出的绝对值上限。加速度计最多读到 157 m/s²（约 16 g），陀螺仪最多 34.9 rad/s，和真实 IMU 的量程一样会“顶格”。
  • noise：不会给读数加噪声。MuJoCo 从 3.1.4 起就去掉了自动加噪声的功能（4.0.1 也一样），这个属性现在只是个“备注栏”，存一下标准差（编译后在 m.sensor_noise 里）留给用户自己用。想要带噪声的读数，要自己在 Python 里加。

按名字读取：

acc = d.sensor("imu-torso-linear-acceleration").data   # 长度 3 的数组
gyr = d.sensor("imu-torso-angular-velocity").data

先猜一猜

  1. G1 稳稳站在地上不动，躯干加速度计的三个分量大约是多少？是 [0, 0, 0]、[0, 0, -9.81] 还是 [0, 0, +9.81]？
  2. 把机器人抬到空中松手，自由下落时加速度计读多少？
  3. 静止时陀螺仪读多少？

原理：加速度计测的是“比力”

加速度计内部是一块挂在弹簧上的小质量块。它测的是弹簧拉着小质量块的力，除以质量，也就是

\[a_{\text{读数}} = R^\mathsf{T}\,(a - g),\qquad g = (0,\ 0,\ -9.81)\]

其中 \(a\) 是 site 在世界坐标系里的真实加速度，\(R\) 是 site 的姿态矩阵（d.site(...).xmat），\(R^\mathsf{T}\) 把世界坐标下的向量转到 site 坐标系。

  • 静止：\(a = 0\)，读数 \(= R^\mathsf{T}(0, 0, +9.81)\)。地面通过脚、腿、骨盆一路把躯干往上托，弹簧里的力是向上的，所以读到 +9.81 向上。
  • 自由下落：\(a = g\)，读数 \(= 0\)。没有任何东西托着它，这就是“失重”。

这也是 IMU 能估计倾角的原因：静止时读数就是“竖直向上”在 site 坐标系里的方向，看它偏了多少，就知道身体歪了多少。

运行结果（A、B 段）

=== A. 静止站立 t = 1.00 s ===
torso  加速度计 [ 0.028 -0.001  9.81 ]  |a| = 9.810   陀螺仪 [-0.     0.001  0.   ]
pelvis 加速度计 [ 0.011 -0.     9.81 ]  |a| = 9.810   陀螺仪 [-0.     0.001  0.   ]

躯干 IMU 的 z 轴偏离竖直 0.16°
...
=== B. 自由下落 0.1 s ===
躯干加速度计 [-0. -0.  0.]  |a| = 0.000  接触数 0
  • 躯干加速度计 x 分量是 0.028 而不是 0，因为躯干微微往后仰了约 0.16°（IMU 的 x 轴朝前，往后仰时 x 轴稍稍朝上，重力的“反作用”就在 x 上分到一个正分量）：\(9.81 \times \sin 0.16° \approx 0.03\)。把 -gravity 用 R.T 转到躯干坐标系，得到的也是 [0.028, -0.001, 9.81]，和传感器读数在三位小数上一致。再往后的微小差别，来自机器人还在极轻微地晃动（\(a\) 不完全是 0）。
  • 骨盆 IMU 的 x 分量只有 0.011，说明骨盆比躯干仰得少。两个 IMU 装在不同的 body 上，中间隔着三个腰关节，读数不必相同。
  • 自由下落时三个分量都是 0，验证了上面的公式。

4.3 关节传感器：用 MjSpec 补上

g1.xml 只定义了 IMU。关节角度、角速度、电机力矩这些“编码器读数”要自己加。第 3 课学过 MjSpec，这里不改原文件，在脚本里加：

def build_model():
    spec = mujoco.MjSpec.from_file(str(XML))
    S, O = mujoco.mjtSensor, mujoco.mjtObj
    spec.add_sensor(name="knee_L_pos", type=S.mjSENS_JOINTPOS,
                    objtype=O.mjOBJ_JOINT, objname="left_knee_joint")
    spec.add_sensor(name="knee_L_vel", type=S.mjSENS_JOINTVEL,
                    objtype=O.mjOBJ_JOINT, objname="left_knee_joint")
    spec.add_sensor(name="knee_L_frc", type=S.mjSENS_ACTUATORFRC,
                    objtype=O.mjOBJ_ACTUATOR, objname="left_knee_joint")
    spec.add_sensor(name="com", type=S.mjSENS_SUBTREECOM,
                    objtype=O.mjOBJ_BODY, objname="pelvis")
    return spec.compile()

等价的 XML 写法是在 <sensor> 里加：

<jointpos    name="knee_L_pos" joint="left_knee_joint"/>
<jointvel    name="knee_L_vel" joint="left_knee_joint"/>
<actuatorfrc name="knee_L_frc" actuator="left_knee_joint"/>
<subtreecom  name="com" body="pelvis"/>

加完后传感器从 4 个变成 8 个，nsensordata 从 12 变成 18（3 个标量 + 1 个三维）。

先猜一猜

  1. 站立 1 s 后，jointpos 传感器的读数和 d.joint("left_knee_joint").qpos 会完全相等吗？
  2. 左膝的目标角 ctrl 和实际角 qpos 差多少？电机在出力吗？

运行结果

左膝 jointpos 传感器 -0.000488   qpos -0.000488
左膝 jointvel 传感器 -0.000308   qvel -0.000309
左膝 actuatorfrc 传感器 0.2466   actuator_force 0.2466
ctrl - qpos = 0.00049 rad，kp = 500，kv = 9.08
mj_step 之后  传感器 - 状态：pos 6.2e-07  vel 9.4e-07  frc - kp(ctrl-q)+kv*qd -3.2e-04
mj_forward 后 传感器 - 状态：pos 0.0e+00  vel 0.0e+00  frc - kp(ctrl-q)+kv*qd 0.0e+00

两个要点：

  • 刚 mj_step 完，传感器和状态差一点点。 这是因为 mj_step 先算传感器，再积分推进 qpos、qvel（入门教程 3.5 的第 6 步）。所以传感器反映的是这一步积分之前的状态，比当前的 qpos 慢了一个时间步。调用一次 mj_forward，用当前状态重算，差值就变成 0。
  • actuatorfrc 就是 actuator_force，也就是第 2 课的 PD 公式 \(k_p(\text{ctrl}-q) - k_v\dot q\)（未触到 forcerange 时）。左膝有 0.00049 rad 的稳态误差，乘以 kp = 500，电机出力约 0.25 N·m。stand 姿势的膝盖几乎是直的，膝关节基本不用出力。

既然 qpos 随手就能读，为什么还要传感器？三个理由：① 写控制器时只读 sensordata，能强迫自己只用“真机也有”的信息；② 可以集中设 cutoff、加延迟（delay）等，模拟真实传感器的缺陷；③ Studio 和 MuJoCo Live 能直接画传感器曲线。

4.4 脚底接触力：左右脚各扛多少

第 1 课讲过，每只脚底有 4 个半径 5 mm 的小球。站稳时应该正好有 8 个接触。读接触力分三步：

  1. 遍历 d.contact[0:d.ncon]，根据 geom1、geom2 所属的 body 判断这是不是脚、是哪只脚。
  2. 用 mj_contactForce 取出这个接触的力。它给的是接触坐标系下的 [法向, 切向1, 切向2]。
  3. 用 contact.frame 把力转到世界坐标，按脚累加。
def foot_contacts(m, d):
    foot_ids = {m.body(name).id: name for name in FEET}
    total = {name: np.zeros(3) for name in FEET}
    points = []
    f6 = np.zeros(6)
    for i in range(d.ncon):
        c = d.contact[i]
        b1, b2 = m.geom_bodyid[c.geom1], m.geom_bodyid[c.geom2]
        if b2 in foot_ids:            # 力作用在 geom2 上，方向不变
            name, sign = foot_ids[b2], 1.0
        elif b1 in foot_ids:          # 脚是 geom1，作用在脚上的力要反号
            name, sign = foot_ids[b1], -1.0
        else:
            continue
        mujoco.mj_contactForce(m, d, i, f6)       # 接触坐标系：[法向, 切向1, 切向2]
        frame = c.frame.reshape(3, 3)             # 每一行是接触坐标系的一根轴
        f_world = frame.T @ f6[:3]                # 换到世界坐标
        total[name] += sign * f_world
        points.append(c.pos[:2].copy())
    return total, np.array(points)

几个容易踩的坑：

  • frame 按行存轴。frame[0:3] 是法向（接触坐标系的 x 轴），frame[3:6]、frame[6:9] 是两个切向。reshape 成 3×3 后，每一行是一根轴，所以“接触坐标 → 世界坐标”要乘 frame.T。
  • 力的方向。法向从 geom1 指向 geom2，mj_contactForce 得到的是作用在 geom2 上的力。平面和别的 geom 相撞时，MuJoCo 总把平面排在 geom1，所以这里地面 floor 总是 geom1、脚总是 geom2，sign 都是 +1。写成通用代码时别忘了反号的情况。
  • condim。G1 脚底球是 condim="3"，只有法向和两个切向，后 3 个力矩分量都是 0。

4.5 质心与支撑多边形

质心：d.subtree_com[i] 是以 body i 为根的子树的质心（世界坐标）。subtree_com[0] 是整个场景（这里就是整台机器人）的质心。也可以用 subtreecom 传感器读，结果一样。

支撑多边形：所有着地接触点在地面上的凸包。一个静止的物体，质心的竖直投影必须落在支撑多边形里面，否则重力会产生一个把它掀翻的力矩。

脚本用单调链算法求凸包（convex_hull），再算质心投影到凸包边界的有符号距离（margin）：在里面为正，在外面为负。凸包退化成一个点或一条线段（比如只剩脚掌一条侧棱着地）时，支撑区没有“面积”，质心不可能在“里面”，距离记为负。

  • 支撑区左右宽 29.7 cm、前后只有 17.0 cm。人形机器人前后方向的“底盘”很浅。

4.6 推它一下

C 段从 t = 1.0 s 起，在躯干上加一个 30 N、朝 +y（机器人左侧）的力，持续 0.2 s：

d.xfrc_applied[torso, :3] = push if pushing else 0

xfrc_applied 是施加在 body 质心上的世界坐标外力，第 5 课会专门讲。这里只当作“轻轻推一下”。每一步都记下 IMU、左右脚竖直力、质心和裕度，存到 output/04_push_log.csv，并画成 output/04_senses.png。

对照 04_senses.png 的四个子图（橙色区间是推力作用的 0.2 s）：

  • 陀螺仪：x 分量（绕前进方向的侧倾）立刻变负，最大 0.116 rad/s。绕 +x 轴的正转动会让身体往 −y 倒，往 +y 倒就是负的。
  • 加速度计：推力一加上，y 分量马上跳到 +1.49 m/s²（躯干被推着往左加速）；推力撤掉的瞬间跳到 −1.96 m/s²（脚和腿把它往回拉）。z 分量一直在 9.81 附近。
  • 脚底力：推的 0.2 s 里，左脚从约 163 N 涨到 296.9 N，右脚降到 30.4 N。左右合计基本贴着体重那条虚线。之后左右来回摆了几次，到 t ≈ 2.4 s 左右才回到各一半。
  • 质心裕度：几乎没动，一直是 5.3 cm 左右。质心只往左偏了 1.33 cm，而最近的边是后跟那条边，侧推根本没让它离后跟更近。最小值 5.29 cm 出现时，8 个脚底球有 1 个短暂离地，只剩 7 个接触点。

  4. 压力中心。 把每个接触点的位置按竖直力加权平均，得到压力中心（CoP）：\(\text{CoP} = \sum_i f_{z,i}\,p_i / \sum_i f_{z,i}\)。写一段代码，算出静止时和往左推 30 N 过程中的 CoP，和质心投影比较。
  5. 给 IMU 加噪声。 4.2 节说 noise 属性不会自动生效。在 C 段的记录循环里，自己给陀螺仪读数加上标准差为 m.sensor_noise[...] 的高斯噪声，再画一次第一个子图。

def cop(m, d):
    """压力中心：各接触点按竖直力加权平均。"""
    f6, num, den = np.zeros(6), np.zeros(2), 0.0
    for i in range(d.ncon):
        c = d.contact[i]
        mujoco.mj_contactForce(m, d, i, f6)
        fz = (c.frame.reshape(3, 3).T @ f6[:3])[2]   # 地面是 geom1，力作用在脚上
        num += fz * c.pos[:2]
        den += fz
    return num / den
