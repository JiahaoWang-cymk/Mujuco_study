Unity 插件#

Unity Plug-in

简介#

Introduction

MuJoCo Unity 插件（plug-in）使 Unity 编辑器和运行时能够使用 MuJoCo 物理引擎。用户可以导入 MJCF 文件并在编辑器中编辑模型。该插件在大多数方面依赖 Unity（资源、游戏逻辑、仿真时间），但使用 MuJoCo 来决定物体如何运动，从而让设计者可以访问 MuJoCo 的完整 API。

The MuJoCo Unity plug-in allows the Unity Editor and runtime to use the MuJoCo physics engine. Users can import MJCF files and edit the models in the Editor. The plug-in relies on Unity for most aspects – assets, game logic, simulation time – but uses MuJoCo to determine how objects move, giving the designer access to MuJoCo’s full API.

另有一个使用 MuJoCo Unity 插件的示例项目，是一组入门教程，可在独立仓库中获取。

An example project using MuJoCo’s Unity plugin in a set of introductory tutorials are also available as a standalone repository.

安装说明#

Installation instructions

插件目录包含一个 package.json 文件。Unity 的包管理器（Package Manager）会识别该文件，并将插件的 C# 代码库导入到您的项目中。此外，Unity 还需要 MuJoCo 的原生库，可以在对应的平台压缩包中找到。如果您只想使用该插件而不想开发它，应当使用仓库中与特定版本对应的稳定提交，这些提交由 git 标签标识。请使用 git 检出已克隆仓库的相应版本（git checkout 3.X.Y，其中 X 和 Y 指定引擎版本）。直接使用仓库的 main 分支可能与 MuJoCo 的最新发布版二进制文件不兼容。

The plug-in directory includes a package.json file. Unity’s package manager recognizes this file and will import the plug-in’s C# codebase to your project. In addition, Unity also needs the native MuJoCo library, which can be found in the corresponding platform archive. If you wish to simply use the plug-in and not develop it, you should use one of the version-specific stable commits of the repository, identified by git tags. Check out the relevant version of the cloned repository with git (git checkout 3.X.Y where X and Y specify the engine version). Simply using the main branch of the repository may not be compatible with the most recent release binary of MuJoCo.

在 Unity 2020.2 及更高版本上，导入包时包管理器会查找原生库文件并将其复制到包目录。您也可以手动将原生库复制到包目录并重命名，请参见下面各平台的具体说明。该库也可以复制到项目 Assets 目录下的任意位置。

On Unity version 2020.2 and later, the Package Manager will look for the native library file and copy it to the package directory when the package is imported. Alternatively, you can manually copy the native library to the package directory and rename it, see platform-specific instructions below. The library can also be copied into any location under your project’s Assets directory.

MacOS#

MuJoCo 应用至少需要运行一次，才能使用原生库，目的是将该库注册为受信任的二进制文件。然后，从 /Applications/MuJoCo.app/Contents/Frameworks/mujoco.framework/Versions/Current/libmujoco.4.0.2.dylib 复制动态库文件（可以通过浏览 MuJoCo.app 的内容找到它），并将其重命名为 mujoco.dylib。

The MuJoCo app needs to be run at least once before the native library can be used, in order to register the library as a trusted binary. Then, copy the dynamic library file from /Applications/MuJoCo.app/Contents/Frameworks/mujoco.framework/Versions/Current/libmujoco.4.0.2.dylib (it can be found by browsing the contents of MuJoCo.app) and rename it as mujoco.dylib.

Linux#

将 tar.gz 压缩包解压到 ~/.mujoco。然后从 ~/.mujoco/mujoco-4.0.2/lib/libmujoco.so.4.0.2 复制动态库，并将其重命名为 libmujoco.so。

Expand the tar.gz archive to ~/.mujoco. Then copy the dynamic library from ~/.mujoco/mujoco-4.0.2/lib/libmujoco.so.4.0.2 and rename it as libmujoco.so.

Windows#

将 zip 压缩包解压到用户目录下名为 MuJoCo 的目录中，并复制文件 MuJoCo\bin\mujoco.dll。

Expand the zip archive to a directory called MuJoCo in your user directory, and copy the file MuJoCo\bin\mujoco.dll.

使用插件#

Using the plug-in

导入器#

Importer

导入器通过编辑器的 Asset 菜单调用：点击 "Import MuJoCo Scene"，然后选择包含模型 MJCF 规范的 XML 文件。

The importer is invoked from the Editor’s Asset menu: click on “Import MuJoCo Scene” and select the XML file with your model’s MJCF specification.

上下文菜单#

Context menus

  • 右键单击 geom 组件会提供两个选项：

    Right-clicking a geom component offers two options:

    • "Add mesh renderer" 会向同一游戏对象添加用于渲染该 geom 的组件：一个标准的 MeshRenderer 和一个 MjMeshFilter，后者会创建一个程序化网格，当 geom 的形状属性改变时该网格会被重新创建。

      “Add mesh renderer” adds components to the same game object that render the geom: a standard MeshRenderer and a MjMeshFilter that creates a procedural mesh that is recreated when the geom shape properties change.

    • "Convert to free object" 会添加两个新的游戏对象：一个带有 MjBody 组件的父对象，以及一个带有 MjFreeJoint 组件的同级对象。这使得原先静止的 geom 可以在场景中自由移动。此操作仅适用于 "world" geom，即当前没有 MjBody 父对象的那些 geom。

      “Convert to free object” adds two new game objects: a parent with an MjBody component and a sibling with an MjFreeJoint component. This allows the previously static geom to move about freely in the scene. This action only applies to “world” geoms – those that do not currently have an MjBody parent.

  • 右键单击 Unity Collider 会提供在同一游戏对象上 "Add a matching MuJoCo geom" 的选项。请注意，这并不构成对物理的完整转换，Rigidbody、ArticulationBody 和 Joint 的配置仍然需要手动重新创建。

    Right-clicking a Unity Collider offers the option to “Add a matching MuJoCo geom” to the same game object. Note that this does not comprise a complete conversion of the physics – Rigidbody, ArticulationBody and Joint configurations still need to be recreated manually.

鼠标弹簧#

Mouse spring

当所选游戏对象带有 MjBody 组件时，可以在 Scene 视图中通过按住 Ctrl 并向左拖动，朝鼠标光标方向对该刚体施加弹簧力。弹簧力原点的三维位置，是通过将鼠标位置投影到由相机 X 方向和世界 Y 方向定义的平面上得到的。同时按住 Shift 键会将投影平面改为与世界的 X 轴和 Z 轴平行。

When the selected game object has an MjBody component, spring forces can be applied to this body towards the mouse cursor through a control-left-drag action in the Scene view. The 3D position of the spring force origin is found by projecting the mouse position on a plane defined by the camera X direction and the world Y direction. Adding the shift key changes the projection plane to be parallel to the world’s X and Z axes.

给 Unity 用户的提示#

Tips to Unity users

  • 如果遇到任何编译或运行时错误，系统的状态是未定义的。因此，我们建议在控制台窗口中打开 “Error Pause”。

    If any compilation or runtime errors are encountered, the state of the system is undefined. Therefore, we recommend turning on “Error Pause” in the console window.

  • 在 PhysX 中，每个 Rigidbody 都是“自由刚体”。相比之下，MuJoCo 要求显式指定关节才能运动。为方便起见，我们提供了一个上下文菜单，用于“释放”世界 geom（即没有任何 MjBody 祖先的 MjGeom 组件），其做法是添加一个父 MjBody 和一个同级 MjFreeJoint。

    In PhysX, every Rigidbody is a “free body”. In contrast, MuJoCo requires explicit specification of joints for mobility. For convenience, we provide a context menu for “freeing” a world geom (i.e., an MjGeom component without any MjBody ancestor) by adding a parent MjBody and a sibling MjFreeJoint.

  • 该插件不支持没有物理实体的碰撞检测（collision detection），因此没有内置的触发器碰撞体概念。接触力是否存在，可以通过添加 touch 传感器并读取其 SensorReading 值来获得（该值对应法向力，参见 touch 传感器文档 <sensor-touch>）。

    The plug-in doesn’t support collision detection without physical presence, so there is no built-in notion of trigger colliders. The presence or absence of a contact force can be read by adding a touch sensor and reading its SensorReading value (which will correspond to the normal force, see touch sensor documentation <sensor-touch>).

设计原则#

Design principles

该插件的设计在 MJCF 元素与 Unity 组件之间提供了一一映射。为了使用 MuJoCo 仿真一个 Unity 场景（例如，用户在编辑器中点击 “play” 按钮时），插件会：

The plug-in design provides a one-to-one mapping between MJCF elements and Unity components. In order to simulate a Unity scene (e.g., when the user hits the “play” button in the Editor) using MuJoCo, the plug-in:

  1. 扫描场景中 GameObject 层级结构里的 MuJoCo 组件。

    Scans the GameObject hierarchy in the scene for MuJoCo components.

  2. 创建 MJCF 描述，并将其传递给 MuJoCo 的编译器。

    Creates an MJCF description and passes it to MuJoCo’s compiler.

  3. 通过 MuJoCo 数据结构中的相应索引，将每个组件绑定到 MuJoCo 运行时。该索引用于在仿真过程中更新 Unity 的变换。

    Binds every component to the MuJoCo runtime via the corresponding index in MuJoCo’s data structures. This index is used for updating Unity’s transforms during simulation.

这一设计原则有若干影响：

This design principle has several implications:

  • Unity 组件的大多数字段直接对应于 MJCF 属性。因此，用户可以参阅 MuJoCo 文档了解不同取值的具体语义。

    Most fields of the Unity components correspond directly to MJCF attributes. Therefore, the user can refer to the MuJoCo documentation for details on the semantics of different values.

  • MuJoCo 组件在 GameObject 层级结构中的布局决定了最终 MuJoCo 模型的布局。因此，我们采用一条设计规则：每个游戏对象最多只能有一个 MuJoCo 组件。

    The layout of MuJoCo components in the GameObject hierarchy determines the layout of the resulting MuJoCo model. Therefore, we adopt a design rule that every game object must have at most one MuJoCo component.

  • 我们依赖 Unity 进行空间配置，这要求对向量分量进行重排（swizzle），因为 Unity 使用左手坐标系且以 Y 为竖直轴，而 MuJoCo 使用右手坐标系且以 Z 为竖直轴。

    We rely on Unity for spatial configuration, which requires vector components to be swizzled since Unity uses left-handed frames with Y as the vertical axis, while MuJoCo uses right-handed frames with Z as the vertical axis.

  • Unity 的变换缩放会影响整个游戏对象子树的位置、朝向和比例。但是，MuJoCo 不支持倾斜圆柱体和胶囊体的碰撞（倾斜的球体可通过椭球图元来支持）。geom 和 site 的 gizmo 会忽略这种倾斜（与 PhysX 碰撞体类似），并始终显示该图元在物理计算中呈现的形状。

    Unity transform scaling affects positions, orientations, and scale of the entire game object subtree. However, MuJoCo doesn’t support collision of skewed cylinders and capsules (skewed spheres are supported via the ellipsoid primitive). The gizmo for geoms and sites ignores this skew (similarly to PhysX colliders), and will always show the primitive shape as it will appear to the physics.

  • 在运行时，更改组件字段的值不会触发场景重建，因此不会对物理产生即时影响。不过，新值会在下一次场景重建时加载。

    During runtime, changing values of component fields will not trigger scene recreation, so it will have no immediate effect on the physics. However, the new values will be loaded upon the next scene recreation.

只要可能，我们都按 Unity 的方式行事：重力从 Unity 的物理设置中读取，仿真步长从 Unity 时间管理器（Time Manager）的 Fixed Timestep 中读取。外观的所有方面（例如网格、材质和纹理）都由 Unity 的资源管理器（Asset Manager）处理，RGBA 规范则通过材质资源来完成。

Wherever possible, we do things the Unity Way: gravity is read from Unity’s physics settings, and the simulation step is read from Unity’s Time Manager’s Fixed Timestep. All aspects of appearance (e.g., meshes, materials, and textures) are handled by Unity’s Asset Manager, and RGBA specifications are done using material assets.

实现说明#

Implementation notes

导入器工作流程#

Importer workflow

当用户选择一个 MJCF 文件时，导入器首先在 MuJoCo 中加载该文件，将其保存到临时位置，然后处理生成的已保存文件。这有以下几方面的效果：

When the user selects an MJCF file, the importer first loads the file in MuJoCo, saves it to a temporary location, and then processes the generated saved file. This has several effects:

  • 它会验证 MJCF，我们可以保证保存的 MJCF 符合模式。

    It validates the MJCF - we are guaranteed that the saved MJCF matches the schema.

  • 它会验证资源（材质、网格、纹理）并将这些资源导入 Unity，同时为 geom 的 RGBA 规范创建新的材质资源。

    It validates the assets (materials, meshes, textures) and imports these assets into Unity, as well as creating new material assets for geom RGBA specification.

  • 它使导入器能够处理 <include> 元素，而无需复制 MuJoCo 的文件系统工作流程。

    It allows the importer to handle <include> elements without replicating MuJoCo’s file-system workflow.

在 Unity 中，没有与 MJCF 的“级联” <default> 子句等价的机制。因此，Unity 中的组件反映的是应用了所有相关默认类（default class）之后相应元素的状态，原始 MJCF 中的类结构会被丢弃。

In Unity, there is no equivalent to MJCF’s “cascading” <default> clauses. Therefore, components in Unity reflect the corresponding elements’ state after applying all the relevant default classes, and the class structure in the original MJCF is discarded.

MuJoCo 场景#

The MuJoCo Scene

创建 MuJoCo 场景时，MjScene 组件首先扫描场景中 MjComponent 的所有实例。每个组件使用 Unity 场景的空间结构创建自己的 MJCF 元素，以描述模型的初始参考姿态（在 MuJoCo 中称为 qpos0）。MjScene 按照各游戏对象的层级结构组合这些 XML 元素，并创建物理模型的单个 MJCF 描述。然后它创建运行时结构体 mjModel 和 mjData，并通过识别每个组件的唯一索引将其绑定到运行时。

When a MuJoCo scene is created, the MjScene component first scans the scene for all instances of MjComponent. Each component creates its own MJCF element using Unity scene’s spatial structure to describe the model’s initial reference pose (called qpos0 in MuJoCo). MjScene combines these XML elements according to the hierarchy of the respective game objects and creates a single MJCF description of the physics model. It then creates the runtime structs mjModel and mjData, and binds each component to the runtime by identifying its unique index.

在运行时，MjScene.FixedUpdate() 调用 mj_step，然后根据绑定时识别出的索引 MjComponent.MujocoId 同步每个游戏对象的状态。当且仅当场景中包含任何 MuJoCo 组件时，应用启动时（例如用户点击 “play” 时）会自动添加 MjScene 组件。如果您的应用初始化阶段涉及在添加游戏对象和组件的同时推进物理，可以在初始化阶段结束时调用 MjScene.CreateScene()。

During runtime, MjScene.FixedUpdate() calls mj_step, and then synchronizes the state of each game object according to the index MjComponent.MujocoId identified at binding time. An MjScene component is added automatically when the application starts (e.g., when the user hits “play”) if and only if the scene includes any MuJoCo components. If your application’s initialization phase involves ticking the physics while adding game objects and components, you can call MjScene.CreateScene() when the initialization phase is over.

场景重建通过以下方式保持物理和状态的连续性：

Scene recreation maintains continuity of physics and state in the following way:

  1. 缓存关节的位置和速度。

    The position and velocity of joints are cached.

  2. 重置 MuJoCo 的状态（重置为 qpos0）并同步 Unity 变换。

    MuJoCo’s state is reset (to qpos0) and Unity transforms are synchronized.

  3. 生成新的 XML，创建一个模型，对于保留下来的关节，其 qpos0 与前一个模型相同。

    A new XML is generated, creating a model that has the same qpos0 as the previous one for the joints that persisted.

  4. 从缓存中设置 MuJoCo 状态（针对保留下来的关节），并同步 Unity 变换。

    The MuJoCo state (for the joints that persisted) is set from the cache, and Unity transforms are synchronized.

MuJoCo 具有动态场景编辑功能（通过 mjSpec），但 Unity 插件尚不支持这一点。因此，添加和移除 MuJoCo 组件会导致整个场景重建。对于大型模型或这种情况频繁发生时，这可能开销很大。我们打算在插件的未来版本中解除这一性能限制。

MuJoCo has functionality for dynamic scene editing (through mjSpec), however, this is not yet supported in the Unity plugin. Therefore, adding and removing MuJoCo components causes complete scene recreation. This can be expensive for large models or if it happens frequently. We intend to lift this performance limitation to be in a future versions of the plugin.

全局设置#

Global Settings

“每个元素对应一个组件”的一个例外是全局设置（Global Settings）组件。该组件负责 MJCF 中固定大小的单例全局元素所包含的所有配置选项。目前它保存与 <option> 和 <size> 元素对应的信息，将来如果 <compiler> 元素中有与 Unity 插件相关的字段，也将用于该元素。

An exception to the one-element-per-one-component is the Global Settings component. This component is responsible for all the configuration options that are included in the fixed-size, singleton, global elements of MJCF. Currently it holds information that corresponds to the <option> and <size> elements, and in the future it will also be used for the <compiler> element, if/when fields there will be relevant to the Unity plug-in.

在应用运行时调用导入器#

Invoking the importer at application runtime

导入器由类 MjImporterWithAssets 实现，它是 MjcfImporter 的子类。这个父类接受一个 MJCF 字符串并生成组件的层级结构。它可以在运行（play）时调用（不涉及编辑器功能），并且不会调用 MuJoCo 库的任何函数。当 MuJoCo 模型是以程序方式生成的（例如通过某种进化过程），和/或导入 MJCF 仅仅是为了转换（例如转换为 PhysX 或 URDF）时，这很有用。由于它无法与 Unity 的 AssetManager（编辑器的一项功能）交互，因此该类的功能受到限制。具体而言：

The importer is implemented by the class MjImporterWithAssets, which is a subclass of MjcfImporter. This parent class takes an MJCF string and generates the hierarchy of components. It can be invoked at play-time (it doesn’t involve Editor functionality), and it doesn’t invoke any functions of the MuJoCo library. This is useful when MuJoCo models are generated procedurally (e.g., by some evolutionary process) and/or when an MJCF is imported only to be converted (e.g., to PhysX, or URDF). Since it cannot interact with Unity’s AssetManager (which is a feature of the Editor), this class’s functionality is restricted. Specifically:

  • 它会忽略所有资源（包括碰撞网格）。

    It ignores all assets (including collision meshes).

  • 它会忽略视觉效果（包括 RGBA 规范）。

    It ignores visuals (including RGBA specifications).

MuJoCo 传感器组件#

MuJoCo sensor components

MuJoCo 定义了许多传感器，我们担心为每个传感器创建单独的 MjComponent 类会导致大量代码重复。因此，我们按照被测量属性所属的对象类型（执行器 / 刚体 / geom / 关节 / site）以及所测数据的类型（标量 / 向量 / 四元数）来创建类。

MuJoCo defines many sensors, and we were concerned that creating a separate MjComponent class for each would lead to a lot of code duplication. Therefore, we created classes according to the type of object (actuator / body / geom / joint / site) whose properties are measured, and the type (scalar / vector / quaternion) of the measured data.

网格形状#

Mesh Shapes

该插件允许使用任意 Unity 网格进行 MuJoCo 碰撞。在模型编译时，MuJoCo 调用 qhull 创建网格的凸包，并将其用于碰撞。目前计算出的凸包在 Unity 中不可见，但我们打算在未来版本中将其暴露出来。

The plug-in allows using arbitrary Unity meshes for MuJoCo collision. At model compilation, MuJoCo calls qhull to create a convex hull of the mesh, and uses that for collisions. Currently the computed convex hull is not visible in Unity, but we intend to expose it in future versions.

高度场#

Height fields

MuJoCo 的 hfield 在 Unity 中通过地形（terrain）游戏对象来表示。这使得可以使用 Unity 中提供的地形编辑工具来生成用于与 MuJoCo 碰撞的形状。在 Unity geom 组件中选择 hfield 类型时，右键上下文菜单提供了向场景添加相应 Unity 地形的实用功能。地形中的数据会与仿真动态保持同步。

MuJoCo hfields are represented in Unity through terrain gameobjects. This allows the use of the terrain editing tools available in Unity to generate shapes for collisions with MuJoCo. When selecting hfield type in the Unity geom component, the right click context menu provides utility to add the corresponding Unity terrain to the scene. The data from the terrain is dynamically kept in sync with the simulation.

MuJoCo 插件#

MuJoCo plugins

当前版本的 Unity 包不支持加载使用 MuJoCo 插件（例如执行器）的 MJCF 场景。为此添加基本功能将是即将发布的版本的一部分。

The current version of the Unity package does not support loading MJCF scenes that use MuJoCo plugins such as actuator . Adding basic functionality to do this will be part of an upcoming release.

与外部进程交互#

Interaction with External Processes

Roboti 的 Unity 版 MuJoCo 插件在外部 Python 进程中推进仿真，仅使用 Unity 进行渲染（rendering）。相比之下，我们的插件依赖 Unity 来推进仿真。在外部进程“驱动”仿真的情况下使用我们的插件应该是可行的，例如设置 qpos，调用 mj_kinematics，同步变换，然后使用 Unity 进行渲染或计算游戏逻辑。要与外部进程建立通信，可以使用 Unity 的 ML-Agents 包。

Roboti’s MuJoCo plug-in for Unity steps the simulation in an external Python process, and uses Unity only for rendering. In contrast, our plug-in relies on Unity to step the simulation. It should be possible to use our plug-in while an external process “drives” the simulation, for example by setting qpos, calling mj_kinematics, synchronizing the transforms, and then using Unity to render or compute game logic. In order to establish communication with an external process, you can use Unity’s ML-Agents package.
