# 第 0 课　装好环境：离线安装与版本核对

**对应入门教程**：2.1–2.5

**本课目标**

- 弄清楚 MuJoCo 4 的 Python 包拆成了哪几块，本课程一共要装哪些包。
- 在能上网的机器上把 wheel 连同依赖一次下全，拷到目标机器上离线安装。
- 运行检查脚本，确认仿真、离屏渲染、画图、写视频都能用。

**预计用时**：0.5–1 小时（不含下载时间）　**前置**：一台能上网的电脑（只用来下载），一台装好 Python 3.11–3.14 的目标机器

---

## 0.1 要装哪些东西

本课程用到的 Python 包：

| 包 | 版本 | 用在哪 |
|---|---|---|
| `mujoco` | 4.0.1 | 每一课。它是个“元包”，自己几乎没有代码，见下文 |
| `numpy` | 随 Python 版本而定 | 每一课，MuJoCo 的数组都是 numpy 数组 |
| `matplotlib` | 3.10.9 | 画曲线、存 PNG 图（多数课都要用） |
| `imageio` + `imageio-ffmpeg` | 2.38.2 + 0.8.1 | 存图片、写 mp4 视频（第 10 课）。`imageio-ffmpeg` 自带一个 ffmpeg 程序，不用另装 |
| `torch`（CPU 版） | 2.15.0+cpu | **可选**。第 9 课可以用它像官方脚本那样加载宇树的行走策略；不装也行，第 9 课的脚本会自动改用 numpy 计算同一个网络 |

### MuJoCo 4 拆包了

MuJoCo 3.x 的时候，`pip install mujoco` 就是一个包。从 4.0.0 起，它拆成了几块：

```text
mujoco 4.0.1（元包，wheel 只有 0.11 MB）
├─ mujoco-core          仿真核心：C 库 + Python 绑定，只依赖 numpy
├─ mujoco-studio        新查看器 MuJoCo Studio 和 Filament 渲染器
│   ├─ mujoco-core
│   ├─ mujoco-studio-wasm   Studio 网页查看器的浏览器端（与平台无关的 wheel）
│   └─ websockets           网页查看器和 Python 之间传数据
├─ glfw + pyopengl      经典 OpenGL 渲染：mujoco.viewer、mujoco.Renderer 要用
└─ numpy
```

不管装的是哪一块，代码里都只写 `import mujoco`。

拆包带来一个离线安装的坑：如果只拷了 `mujoco-4.0.1-py3-none-any.whl` 这一个文件，pip 会报找不到 `mujoco-core`；如果漏了 `mujoco-studio-wasm`，`mujoco-studio` 就装不上，Studio 也就打不开。所以**一定要连同依赖一起下载**。

> 只做无界面仿真（比如在服务器上批量跑实验）时，可以只装 `mujoco-core`，它只依赖 numpy。本课程要用 Studio 看机器人，所以装完整的 `mujoco`。

## 0.2 先查清目标机器的情况

wheel 是“编译好的安装包”，含 C 代码的包要和**操作系统、CPU 架构、Python 版本**三样都对上才能装。文件名里写着这三样，比如：

```text
mujoco_core-4.0.1-cp313-cp313-win_amd64.whl
                  ─────       ─────────
                  Python 3.13  Windows 64 位
```

纯 Python 的包文件名是 `py3-none-any`，哪里都能装。

在**目标机器**上运行下面两条命令，记下结果：

```bash
python -c "import sys, platform; print(sys.version_info[:2], platform.system(), platform.machine())"
python -m pip --version
```

本课程编写时用的机器输出 `(3, 13) Windows AMD64`，pip 25.3。

还可以让 pip 自己列出它认哪些标签：

```bash
python -m pip debug --verbose
```

在 `Compatible tags` 下面，排第一的就是最匹配的标签，比如 `cp313-cp313-win_amd64`。

**支持哪些 Python 版本？** 我们用 0.3 节的方法，对 Windows 64 位逐个版本试了一遍（只解析，不下载）：

| Python | 结果 |
|---|---|
| 3.10 | × `mujoco==4.0.1` 找不到。pip 提示 `4.0.1 Requires-Python >=3.11`，只能装到 3.17.0 |
| 3.11 | √ 但 numpy 只能到 2.4.6、contourpy 只能到 1.3.3（新版要求 3.12+） |
| 3.12、3.13、3.14 | √ 20 个包全部有 wheel |
| 3.15 | × `mujoco` 本身有 wheel，但 `matplotlib==3.10.9` 没有，只能装 3.11.2 |

结论：**用 Python 3.12 或 3.13 最省心**，本课程所有脚本都在 3.13 上跑过。

## 0.3 在能上网的机器上：先列清单

先写一个 `requirements.txt`，把要装的包写进去。版本尽量固定，这样两台机器装出来的一模一样：

```text
# G1 实战课程用到的包
mujoco==4.0.1
numpy
matplotlib==3.10.9
imageio==2.38.2
imageio-ffmpeg==0.8.1
```

numpy 没写版本，是因为它的最新版不支持 Python 3.11，固定了反而在 3.11 上装不上。

在真正下载之前，先让 pip **只解析依赖、不下载、不安装**，把它打算装的东西列成一份报告（需要 pip 22.2 及以上）：

```powershell
python -m pip install --dry-run --ignore-installed --report report.json `
    --only-binary=:all: --platform win_amd64 --python-version 3.13 `
    -r requirements.txt
```

（上面是 PowerShell 写法，行尾用反引号续行；cmd 里用 `^`，Linux/macOS 里用 `\`，或者干脆写成一行。）

几个参数的意思：

- `--dry-run`：只演练，不安装。
- `--ignore-installed`：假装本机什么都没装，否则已经装过的包不会出现在清单里。
- `--report report.json`：把结果写成 JSON。
- `--platform`、`--python-version`：按**目标机器**的平台和 Python 版本来挑 wheel，这样下载机和目标机不一样也没关系。一用这两个参数，pip 就要求同时写 `--only-binary=:all:`（只要 wheel，不要源码包），否则报错。

这一步只会下载各个包的元数据（几 KB 一个），很快。报告里的东西很多，用本课的小脚本整理一下：

```bash
python code/00_read_report.py report.json
```

## 0.4 在能上网的机器上：下载 wheel

清单没问题，就把 `--dry-run` 那条命令换成 `pip download`。参数几乎一样：

```powershell
mkdir wheels
python -m pip download -d wheels `
    --only-binary=:all: --platform win_amd64 --python-version 3.13 `
    -r requirements.txt
```

- `-d wheels`：下载到 `wheels` 目录。
- **不要加 `--no-deps`**，否则只会下来你点名的 5 个，依赖全漏掉。
- `pip download` 没有 `--dry-run`，所以上一节用 `pip install --dry-run` 先看清单。

下完后 `wheels` 里应该正好是上一节表里那 20 个文件。按 PyPI 上登记的大小，Windows + Python 3.13 这一套合计约 94 MB，其中最大的是 `imageio-ffmpeg`（约 39 MB，里面是 ffmpeg 程序）、numpy（约 13 MB）、`mujoco-core`（约 8 MB）。

**目标机器是 Linux 怎么办？** Linux 的 wheel 标签比较多：`mujoco-core`、numpy 用的是 `manylinux_2_28_x86_64`，matplotlib、kiwisolver 用的是 `manylinux_2_17_x86_64`。`--platform` 可以写多次，两个都写上才能把 20 个包配齐：

```bash
python -m pip download -d wheels_linux \
    --only-binary=:all: --platform manylinux_2_28_x86_64 --platform manylinux_2_17_x86_64 \
    --python-version 3.12 -r requirements.txt
```

只写 `manylinux_2_28_x86_64` 一个时，pip 会报 `No matching distribution found for matplotlib==3.10.9`。

### 拷走之前，先在下载机上自检一次

把 `--no-index --find-links wheels` 加到 0.3 节的演练命令里，pip 就只在 `wheels` 目录里找包，等于模拟了目标机器：

```powershell
python -m pip install --dry-run --ignore-installed --no-index --find-links wheels `
    --only-binary=:all: --platform win_amd64 --python-version 3.13 `
    -r requirements.txt
```

最后一行出现 `Would install ...`，列出 20 个包，说明 `wheels` 是齐的。如果少了什么，会看到 `ERROR: No matching distribution found for xxx`，补下那个包就行。

## 0.5 在目标机器上：建虚拟环境、离线安装

把 `wheels` 目录和 `requirements.txt` 拷到目标机器，比如放在 `D:\g1\` 下。

**第一步：建虚拟环境。** 虚拟环境是一个独立的 Python 安装目录，装进去的包不会影响系统里别的项目：

```powershell
cd D:\g1
python -m venv g1-env
g1-env\Scripts\activate          # Linux/macOS：source g1-env/bin/activate
```

激活后，命令行前面会多出 `(g1-env)`。之后每次打开新终端，都要先激活一次。

**第二步：离线安装。**

```powershell
python -m pip install --no-index --find-links wheels -r requirements.txt
```

- `--no-index`：不去 PyPI 找，完全不联网。
- `--find-links wheels`：到 `wheels` 目录里找。

装完用 `python -m pip list` 看一眼，应该能看到 `mujoco`、`mujoco-core`、`mujoco-studio`、`mujoco-studio-wasm` 四个都是 4.0.1。

## 0.6 PyTorch CPU 版（可选）

第 9 课要运行宇树训练好的行走策略 `motion.pt`，它是 PyTorch 的 TorchScript 文件。官方脚本用 `torch.jit.load` 加载它；课程的 `09_walk.py` 没有 PyTorch 时会自动改用 numpy 算同一个网络，所以**不装 torch 也能学完全部课程**。想和官方做法完全一样，或者想在第 9 课对比 torch 和 numpy 两种后端，再按本节装上。我们只做推理，不训练，CPU 版足够，也比 GPU 版小得多。

CPU 版不在 PyPI 上，在 PyTorch 自己的下载站。先演练一次看清单：

```powershell
python -m pip install --dry-run --ignore-installed --report torch.json `
    --only-binary=:all: --platform win_amd64 --python-version 3.13 `
    --index-url https://download.pytorch.org/whl/cpu torch
python code/00_read_report.py torch.json
```

本课程编写时得到 10 个包：`torch 2.15.0+cpu`，以及 `filelock`、`fsspec`、`Jinja2`、`MarkupSafe`、`mpmath`、`networkx`、`setuptools`、`sympy`、`typing_extensions`。版本号里的 `+cpu` 表示这是 CPU 版。

确认无误后下载（单独放一个目录，方便以后只拷它）：

```powershell
mkdir wheels_torch
python -m pip download -d wheels_torch `
    --only-binary=:all: --platform win_amd64 --python-version 3.13 `
    --index-url https://download.pytorch.org/whl/cpu torch
```

`torch-2.15.0+cpu-cp313-cp313-win_amd64.whl` 本身约 127 MB，其余 9 个依赖合计约 11 MB。这个下载站给 Python 3.11–3.15 都提供了 Windows 的 CPU 版 wheel。

拷到目标机器后，在**激活的虚拟环境**里：

```powershell
python -m pip install --no-index --find-links wheels_torch torch
```

## 如果报错

| 现象 | 可能原因 | 解决 |
|---|---|---|
| `ERROR: Could not find a version that satisfies the requirement mujoco==4.0.1`，并提示 `Requires-Python >=3.11` | Python 是 3.10 或更老 | 换 Python 3.12 或 3.13 |
| 离线安装时 `No matching distribution found for mujoco-core`（或 `mujoco-studio-wasm`、`glfw`、`websockets` 等） | 下载时漏了依赖，比如加了 `--no-deps`，或者只拷了几个文件 | 回到 0.4 节，不加 `--no-deps` 重新下载；拷之前先做一次自检 |
| `xxx.whl is not a supported wheel on this platform` | 下载时 `--platform` 或 `--python-version` 和目标机器不一致 | 在目标机器上用 0.2 节的命令确认版本，重新下载对应的 wheel |
| `When restricting platform and interpreter constraints ... --only-binary=:all: must be set` | 用了 `--platform` / `--python-version`，但没写 `--only-binary=:all:` | 照 0.3、0.4 节的写法补上 |
| `Can not use any platform or abi specific options unless installing via '--target' or using '--dry-run'` | 在 `pip install`（不是演练）里用了 `--platform`：pip 不允许把别的平台的包装进当前环境 | 下载用 `pip download`，演练加 `--dry-run`；在目标机器上安装时不要写 `--platform` |
| 加载 G1 那一项报 `Error opening file ...unitree_g1\scene.xml` | `G1实战` 下没有 `models` 目录，或者拷贝时漏了 | 确认 `G1实战\models\unitree_g1\scene.xml` 存在；脚本按自己所在位置找模型，和当前目录无关 |
| PowerShell 里激活虚拟环境报“禁止运行脚本” | 系统的脚本执行策略不允许运行 `Activate.ps1` | 执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`；或者不激活，直接用 `g1-env\Scripts\python.exe` 运行 |
| 从 MuJoCo 3.x 升级后 `import mujoco` 报错或版本混乱 | 4.0 拆包时，旧的 `mujoco` 里的文件挪进了 `mujoco-core`，直接升级会被 pip 误删 | 先 `pip uninstall -y mujoco` 再离线安装；或者干脆新建一个虚拟环境 |
| `No module named 'mujoco.studio'` | 只装了 `mujoco-core` | 补装 `mujoco-studio` 和 `mujoco-studio-wasm` 两个 wheel |
| 离屏渲染那一项报 OpenGL 相关错误 | 远程桌面、虚拟机或没有显示器的 Linux 上没有可用的 OpenGL | Linux 上设环境变量 `MUJOCO_GL=egl`（有 NVIDIA 驱动）或 `MUJOCO_GL=osmesa`（纯软件，较慢）再运行 |
| 写 mp4 那一项报找不到 ffmpeg | 没装 `imageio-ffmpeg` | 确认 `wheels` 里有 `imageio_ffmpeg-*.whl` 并装上 |
| 中文打印成乱码 | 终端编码不是 UTF-8 | PowerShell 里先运行 `chcp 65001`；把输出重定向到文件时，再设 `$env:PYTHONUTF8=1` |

**先猜一猜 1**：8 个。`mujoco`、`mujoco-core`、`mujoco-studio`、`mujoco-studio-wasm`、`websockets`、`glfw`、`PyOpenGL`、`numpy`。只装 `mujoco-core==4.0.1` 则只有 2 个：它自己和 numpy。

**先猜一猜 3**：不能直接用。`mujoco_core-4.0.1-cp313-cp313-win_amd64.whl` 这类带 `cp313` 的 wheel 只能装在 Python 3.13 上。而且 Python 3.11 能用的 numpy 最高到 2.4.6，下载时必须用 `--python-version 3.11` 重新解析一遍。纯 Python 的 `py3-none-any` 包倒是通用的。

**先猜一猜 4 / 观察记录 1**：本课程编写时，100 步用了 4.5–9.0 ms，是实时的 22–45 倍，随电脑当时的负载有明显波动。G1 只有 29 个关节、8 个脚底接触点，单线程 CPU 就能远超实时。第 10 课批量做实验就是靠这一点。

**先猜一猜 5 / 观察记录 2**：骨盆高度从 0.790 m 变到 0.792 m，只抬高了一两毫米（不四舍五入的话是 0.7916 m，约 1.6 mm）。原因是关键帧把骨盆高度直接写成了 0.79 m，在这个高度上 8 个脚底小球都陷进地面约 1.86 mm（`d.contact[i].dist` 为 −1.86 mm）。仿真开始后，接触力把机器人往上顶，0.2 秒后穿透只剩 0.15–0.29 mm。MuJoCo 的软接触本来就允许一点点穿透，第 5 课讲 solref/solimp 时会再遇到。position 执行器一直在用 `stand` 的目标角度撑着，所以它不会倒。第 2 课会细讲。

**观察记录 3**：几乎看不出动作。用同样的设置单独算一遍：1 秒里骨盆只升高了 1.6 mm，29 个关节角变化最大的也只有 0.16°。

**练习 1**：包的数量一样，还是 20 个。纯 Python 的包（`py3-none-any`，比如 `mujoco`、`mujoco-studio-wasm`、`cycler`）文件名不变；含 C 代码的包变成 `cp312-cp312-manylinux_...` 的文件名。`imageio-ffmpeg` 和 `glfw` 虽然是 `py3-none`，也带平台标签（里面装的是对应平台的 ffmpeg 程序和 glfw 动态库），所以也变了。

**练习 2**：只装 `mujoco-core` 只带上 numpy。仿真、`mj_step`、`MjSpec` 都能用；但没有 `glfw` 和 `pyopengl`，`mujoco.Renderer` 离屏渲染和 `mujoco.viewer` 用不了；没有 `mujoco-studio`，Studio 也打不开。官方文档提到可以装 `mujoco-core[rendering]` 补上 `glfw` 和 `pyopengl`。
