可视化#

Visualization

备注

本页由 AI（Claude Sonnet）根据 MuJoCo 官方英文文档（2026-11-16 版）翻译，仅供学习参考；如有出入，以英文原版为准。术语对照见资料包中的 术语表.md 。

MuJoCo 拥有一个独立于任何图形库的原生 3D 可视化（visualization）层。它提供交互式相机控制、基于射线投射的对象拾取、鼠标驱动的力与位姿扰动、可视化选项，并能自动生成装饰性和诊断性的几何体，例如接触点和接触力、等效惯性盒、凸包、运动学树、约束违反量、空间坐标系以及文字标签。这些元素有助于深入了解物理仿真，并帮助在交互式查看器（MuJoCo Studio、simulate.cc）和离屏渲染管线（render.cc）中微调模型。

MuJoCo has a native 3D visualization layer that is independent of any graphics library. It provides interactive camera control, object picking via raycasting, mouse-driven force and pose perturbations, visualization options, and automatic generation of decorative and diagnostic geometry such as contact points and forces, equivalent inertia boxes, convex hulls, kinematic trees, constraint violations, spatial frames, and text labels. These elements provide insight into the physics simulation and help fine-tune models across both interactive viewers (MuJoCo Studio, simulate.cc) and offscreen rendering pipelines (render.cc).

抽象可视化层中的所有数据结构和函数都带有前缀 mjv，并在 mjvisualize.h 中声明：

All data structures and functions in the abstract visualization layer have the prefix mjv and are declared in mjvisualize.h:

  • mjvCamera 和 mjvGLCamera 分别表示高层交互式相机和底层视锥相机。

    mjvCamera and mjvGLCamera represent high-level interactive cameras and low-level frustum cameras.

  • mjvOption 控制哪些元素类别、geom 组和诊断叠加层可见。

    mjvOption controls which element categories, geom groups, and diagnostic overlays are visible.

  • mjvPerturb 跟踪交互式对象选择以及鼠标施加的力和力矩。

    mjvPerturb tracks interactive object selection and mouse-applied forces and torques.

  • mjvScene 和 mjvGeom 保存对 3D 场景及其装饰的完整逐帧几何描述。

    mjvScene and mjvGeom hold a complete per-frame geometric description of the 3D scene and its decorations.

将抽象可视化与渲染（rendering）分离，可使交互和场景逻辑独立于图形 API，并允许多个渲染后端共享相同的相机、选择、扰动和选项机制。经典 OpenGL 渲染器在每一帧都会使用整个 mjvScene，而 Filament 渲染器则根据 mjData 更新其自身的持久场景，仅将 mjvScene 用于瞬态装饰；两者的并排比较参见渲染一章。第三方渲染器也可以直接使用 mjvScene。

Separating abstract visualization from rendering keeps interaction and scene logic independent of graphics APIs and allows multiple rendering backends to share the same camera, selection, perturbation, and option mechanisms. The classic OpenGL renderer consumes the entire mjvScene on every frame, while the Filament renderer updates its own persistent scene from mjData and uses mjvScene only for transient decorations; see the Rendering chapter for a side-by-side comparison. Third-party renderers can also consume mjvScene directly.

相机#

Cameras

相机对象有两种类型：一种是以独立数据结构 mjvCamera 表示的抽象相机，另一种是以数据结构 mjvGLCamera（也别名为 mjrCamera）表示的底层相机，后者嵌入在 mjvScene 中，或通过 mjv_camera2GLCamera 直接计算得到。存在抽象相机时，它被用来自动计算渲染器所使用的底层相机参数。或者，用户也可以绕过抽象相机机制，直接设置底层相机参数，如下文虚拟现实一节所述。

There are two types of camera objects: an abstract camera represented with the stand-alone data structure mjvCamera, and a low-level camera represented with the data structure mjvGLCamera (also aliased as mjrCamera) which is embedded in mjvScene or computed directly via mjv_camera2GLCamera. When present, the abstract camera is used to automatically compute the low-level camera parameters consumed by the renderer. Alternatively, the user can bypass the abstract camera mechanism and set the low-level camera parameters directly, as discussed in the Virtual reality section below.

抽象相机可以表示三种不同的相机类型，由 mjvCamera.type 决定。可能的设置由枚举 mjtCamera 定义：

The abstract camera can represent three different camera types as determined by mjvCamera.type. The possible settings are defined by the enum mjtCamera:
mjCAMERA_FREE

这是最常用的抽象相机。它可以用鼠标自由移动。它具有注视点、到注视点的距离、方位角和仰角；不允许绕视线方向扭转。函数 mjv_moveCamera 是一个鼠标钩子，用于通过鼠标交互式地控制所有这些相机属性。simulate.cc 首次启动时使用的就是自由相机。

This is the most commonly used abstract camera. It can be freely moved with the mouse. It has a lookat point, distance to the lookat point, azimuth, and elevation; twist around the line of sight is not allowed. The function mjv_moveCamera is a mouse hook for controlling all these camera properties interactively with the mouse. When simulate.cc first starts, it uses the free camera.
mjCAMERA_TRACKING

这与自由相机类似，只是注视点不再是自由参数，而是与 id 由 mjvCamera.trackbodyid 给出的 MuJoCo body 耦合。每次更新时，注视点被设置为以指定 body 为根的运动学子树的质心。此外还有一些滤波处理，以产生平滑的相机运动。距离、方位角和仰角由用户控制，不会被自动修改。这对于在不转动相机的情况下跟踪运动中的 body 很有用。要在 simulate.cc 中从自由相机切换到跟踪相机，请按住 Ctrl 并在目标 body 上右键双击。按 Esc 可返回自由相机。

This is similar to the free camera, except the lookat point is no longer a free parameter but instead is coupled to the MuJoCo body whose id is given by mjvCamera.trackbodyid. At each update, the lookat point is set to the center of mass of the kinematic subtree rooted at the specified body. There is also some filtering which produces smooth camera motion. The distance, azimuth, and elevation are controlled by the user and are not modified automatically. This is useful for tracking a body as it moves around, without turning the camera. To switch from the free to the tracking camera in simulate.cc, hold Ctrl and right-double-click on the body of interest. Press Esc to go back to the free camera.
mjCAMERA_FIXED

这指的是在模型中显式定义的相机，不同于仅存在于可视化器中、并未在模型中定义的自由相机和跟踪相机。模型相机的 id 由 mjvCamera.fixedcamid 给出。该相机是固定的，意思是可视化器不能改变其位姿或任何其他参数。但是，仿真器会在每个时间步计算相机位姿，如果该相机附着在运动的 body 上，或处于跟踪或瞄准模式，它就会移动。

This refers to a camera explicitly defined in the model, unlike the free and tracking cameras which only exist in the visualizer and are not defined in the model. The id of the model camera is given by mjvCamera.fixedcamid. This camera is fixed in the sense that the visualizer cannot change its pose or any other parameters. However the simulator computes the camera pose at each time step, and if the camera is attached to a moving body or is in tracking or targeting mode, it will move.
mjCAMERA_USER

这表示在更新期间忽略抽象相机，并且底层 OpenGL 相机不会改变。这等价于完全不指定抽象相机，即在下文所述的更新函数中将 NULL 指针传给 mjvCamera。

This means that the abstract camera is ignored during an update and the low-level OpenGL cameras are not changed. It is equivalent to not specifying an abstract camera at all, i.e., passing a NULL pointer to mjvCamera in the update functions explained below.

底层 mjvGLCamera 决定实际的渲染。mjvScene 中嵌入了两个这样的相机，每只眼睛一个。每个相机具有位置、前向和上向。前向对应于相机坐标系的负 Z 轴，而上向对应于正 Y 轴。此外还有 OpenGL 意义上的视锥，只不过我们存储的是左右视锥边缘的平均值，然后在渲染期间根据视口的宽高比、并假设像素宽高比为 1:1，计算出实际的边缘。两个相机位置之间的距离对应于瞳距（ipd）。当底层相机参数根据抽象相机自动计算时，对于自由相机和跟踪相机，瞳距以及垂直视场角（fovy）取自 mjModel.vis.global.ipd/fovy，对于模型中定义的相机，则取自相机专属的 mjModel.cam_ipd/fovy。当未启用立体模式（由 mjvScene.stereo 决定）时，两只眼睛的相机数据会在渲染期间于内部取平均。

The low-level mjvGLCamera is what determines the actual rendering. There are two such cameras embedded in mjvScene, one for each eye. Each has position, forward and up directions. Forward corresponds to the negative Z axis of the camera frame, while up corresponds to the positive Y axis. There is also a frustum in the sense of OpenGL, except we store the average of the left and right frustum edges and then during rendering compute the actual edges from the viewport aspect ratio assuming 1:1 pixel aspect ratio. The distance between the two camera positions corresponds to the inter-pupillary distance (ipd). When the low-level camera parameters are computed automatically from an abstract camera, the ipd as well as vertical field of view (fovy) are taken from mjModel.vis.global.ipd/fovy for free and tracking cameras, and from the camera-specific mjModel.cam_ipd/fovy for cameras defined in the model. When stereoscopic mode is not enabled, as determined by mjvScene.stereo, the camera data for the two eyes are internally averaged during rendering.

选择#

Selection

在许多应用中，我们需要点击某个点并确定该点/像素所属的 3D 对象。这通过函数 mjv_select 完成，它使用射线碰撞。射线碰撞功能属于引擎层，不依赖可视化器（实际上它也用于独立于可视化地仿真测距仪传感器），但选择函数是在可视化器中实现的，因为它需要相机和视口的信息。

In many applications we need to click on a point and determine the 3D object to which this point/pixel belongs. This is done with the function mjv_select, which uses ray collisions. Ray collisions functionality is engine-level and does not depend on the visualizer (indeed it is also used to simulate rangefinder sensors independent of visualization), but the select function is implemented in the visualizer because it needs information about the camera and viewport.

函数 mjv_select 返回指定窗口坐标处的 geom 的索引，如果该坐标处没有 geom 则返回 -1。同时还会返回 3D 位置。该函数的使用示例参见代码样例 simulate.cc。在内部，mjv_select 调用引擎层函数 mj_ray，后者又调用逐 geom 的函数 mj_rayMesh、mj_rayHfield 和 mju_rayGeom。用户可以通过直接调用这些函数来实现自定义的选择机制。例如在 VR 应用中，将手持控制器用作可以选择对象的“激光指示器”会很合理。

The function mjv_select returns the index of the geom at the specified window coordinates, or -1 if there is no geom at those coordinates. The 3D position is also returned. See the code sample simulate.cc for an example of how to use this function. Internally, mjv_select calls the engine-level function mj_ray which in turn calls the per-geom functions mj_rayMesh, mj_rayHfield, and mju_rayGeom. The user can implement custom selection mechanisms by calling these functions directly. In a VR application for example, it would make sense to use the hand-held controller as a “laser pointer” that can select objects.

扰动#

Perturbations

事实证明，交互式扰动对于探索模型动力学（dynamics）以及探查闭环控制系统非常有用。用户可以自由实现自己选择的任何扰动机制，方法是将 mjData.qfrc_applied 或 mjData.xfrc_applied 设置为合适的力（分别以广义坐标和笛卡尔坐标表示）。

Interactive perturbations have proven very useful in exploring the model dynamics as well as probing closed-loop control systems. The user is free to implement any perturbation mechanism of their choice by setting mjData.qfrc_applied or mjData.xfrc_applied to suitable forces (in generalized and Cartesian coordinates respectively).

实现交互式扰动所需的所有对象都被归入数据结构 mjvPerturb。其用法在 simulate.cc 中有所展示。其思路是选择一个感兴趣的 MuJoCo body，并为该 body 提供一个参考位姿（即 3D 位置和四元数（quaternion）姿态）。它们存储在 mjPerturb.refpos/quat 中。函数 mjv_movePerturb 是一个鼠标钩子，用于通过鼠标控制参考位姿。函数 mjv_initPerturb 用于在扰动开始时将参考位姿设置为等于所选 body 的位姿，以避免跳变。

All objects needed to implement interactive perturbations are grouped into the data structure mjvPerturb. Its use is illustrated in simulate.cc. The idea is to select a MuJoCo body of interest, and provide a reference pose (i.e., a 3D position and quaternion orientation) for that body. These are stored in mjPerturb.refpos/quat. The function mjv_movePerturb is a mouse hook for controlling the reference pose with the mouse. The function mjv_initPerturb is used to set the reference pose equal to the selected body pose at the onset of perturbation, so as to avoid jumps.

随后，该扰动对象可用于直接移动所选 body（在仿真暂停时，或所选 body 是 mocap 刚体时），或对该 body 施加力和力矩。这分别通过函数 mjv_applyPerturbPose 和 mjv_applyPerturbForce 完成。后一个函数会将所选 body 的外部扰动力写入 mjData.xfrc_applied。但它不会清除其余 body 的 mjData.xfrc_applied，因此建议在用户代码中将其清除，以防所选 body 发生了变化，而某个扰动力是上一个时间步遗留下来的。如果有多个设备可以施加扰动，或者用户代码需要添加来自其他来源的扰动，则用户必须实现必要的逻辑，使 mjData.xfrc_applied 中只存在所需的扰动，并清除所有旧的扰动。

This perturbation object can then be used to move the selected body directly (when the simulation is paused or when the selected body is a mocap body), or to apply forces and torques to the body. This is done with the functions mjv_applyPerturbPose and mjv_applyPerturbForce respectively. The latter function writes the external perturbation force to mjData.xfrc_applied for the selected body. However it does not clear mjData.xfrc_applied for the remaining bodies, thus it is recommended to clear it in user code, in case the selected body changed and some perturbation force was left over from a previous time step. If there is more than one device that can apply perturbations or user code needs to add perturbations from other sources, the user must implement the necessary logic so that only the desired perturbations are present in mjData.xfrc_applied and any old perturbations are cleared.

除了影响仿真之外，扰动对象还能被抽象可视化器识别并被渲染。这是通过添加一条表示位置差的可视化弦，以及一个表示所选 body 参考姿态的旋转立方体来实现的。当启用 mjvOption 中相应的可视化标志时，扰动力本身也可以被渲染。

In addition to affecting the simulation, the perturbation object is recognized by the abstract visualizer and can be rendered. This is done by adding a visual string to denote the positional difference, and a rotating cube to denote the reference orientation of the selected body. The perturbation forces themselves can also be rendered when the corresponding visualization flag in mjvOption is enabled.

可视化选项#

Visualization options

数据结构 mjvOption 控制显示什么，与如何渲染无关。mjv_updateScene 在填充 mjvScene 时使用它，Filament 渲染器也直接读取它，以设置其持久对象的可见性。其字段包括：

The data structure mjvOption controls what is shown, independently of how it is rendered. It is consumed by mjv_updateScene when populating mjvScene and read directly by the Filament renderer to set the visibility of its persistent objects. Its fields are:

  • flags 以 mjtVisFlag 为索引，用于启用各种装饰性和诊断性元素：接触点和接触力、关节和执行器轴、约束违反量、惯性盒、凸包、蒙皮、肌腱、扰动力等等。

    flags, indexed by mjtVisFlag, enable the decorative and diagnostic elements: contact points and forces, joint and actuator axes, constraint violations, inertia boxes, convex hulls, skins, tendons, perturbation forces, and so on.

  • geomgroup、sitegroup、jointgroup、tendongroup、actuatorgroup、flexgroup 和 skingroup 按模型元素的 group 属性切换其可见性。

    geomgroup, sitegroup, jointgroup, tendongroup, actuatorgroup, flexgroup and skingroup toggle the visibility of model elements by their group attribute.

  • label（mjtLabel）和 frame（mjtFrame）分别选择为哪一类对象添加文字标签，以及绘制哪些空间坐标系。

    label (mjtLabel) and frame (mjtFrame) select which category of objects is labeled with text and which spatial frames are drawn.

  • bvh_depth 和 flex_layer 分别选择显示包围体层次结构的哪一层，以及 3D flex 元素的哪一层。

    bvh_depth and flex_layer select which level of the bounding volume hierarchy and which layer of 3D flex elements are shown, respectively.

函数 mjv_defaultOption 将所有字段设置为其默认值，其中第 0、1 和 2 组可见，标志取 mjVISSTRING 中列出的默认值。

The function mjv_defaultOption sets all fields to their defaults, in which groups 0, 1 and 2 are visible and flags take the defaults listed in mjVISSTRING.

场景更新#

Scene update

最后，我们将以上所有元素整合起来，说明 mjvScene 是如何更新的。在经典 OpenGL 渲染器这样的立即模式渲染器中，mjvScene 是渲染阶段的主要输入；而在 Filament 这样的保留模式渲染器中，模型几何体直接根据 mjData 更新，mjvScene 仅用于装饰元素（mjCAT_DECOR）。

Finally, we bring all of the above elements together and explain how mjvScene is updated. In immediate-mode renderers such as the classic OpenGL renderer, mjvScene is the primary input to the rendering stage; in retained-mode renderers such as Filament, model geometry is updated directly from mjData and mjvScene is used only for decorative elements (mjCAT_DECOR).

更新 mjvScene 只需在每一帧调用一次函数 mjv_updateScene。mjvCamera 和 mjvPerturb 是该函数的参数，也可以是 NULL 指针，此时相应的功能被禁用。在 VR 应用中，每一帧还必须设置 mjvScene.camera[n]（n=0,1）的参数；这由 mjv_updateScene 之外的用户代码完成。函数 mjv_updateScene 检查 mjModel 和 mjData，构造所有需要渲染的 geom（依据指定的可视化选项），并用 mjvGeom 对象填充数组 mjvScene.geoms。请注意，mjvGeom 是抽象 geom，与 mjModel 和 mjData 中的仿真 geom 并非一一对应。具体而言，mjvGeom 包含 geom 的位姿、缩放、形状（mjModel 中的基元或网格索引）、材质属性、纹理（mjModel 中的索引）、标注，以及指定如何进行渲染所需的其他一切。mjvScene 还包含从模型复制而来的至多 mjMAXLIGHT 个光源，以及一个头灯（若存在，则位于 0 号光源位置）。

Updating mjvScene can be done with a single call to the function mjv_updateScene at each frame. mjvCamera and mjvPerturb are arguments to this function, or they can be NULL pointers in which case the corresponding functionality is disabled. In VR applications the parameters of mjvScene.camera[n], n=0,1 must also be set at each frame; this is done by user code outside mjv_updateScene. The function mjv_updateScene examines mjModel and mjData, constructs all geoms that need to be rendered (according to the specified visualization options), and populates the array mjvScene.geoms with mjvGeom objects. Note that mjvGeom is an abstract geom, and is not in one-to-one correspondence with the simulation geoms in mjModel and mjData. In particular, mjvGeom contains the geom pose, scale, shape (primitive or mesh index in mjModel), material properties, textures (index in mjModel), labeling, and everything else needed to specify how rendering should be done. mjvScene also contains up to mjMAXLIGHT lights copied from the model, as well as a headlight which is in light position 0 when present.

上述过程是最常见的做法，它在每一帧更新整个场景。此外，我们还提供了两个用于更精细控制的函数。mjv_updateCamera 只更新相机（即将抽象的 mjvCamera 映射到底层的 mjvGLCamera），而不触碰 geom 或光源；另外，mjv_camera2GLCamera 直接返回单个 mjvGLCamera，无需 mjvScene。当仿真暂停而用户在快速移动相机时，或使用 Filament 渲染器时（相机参数通过 mjrfRenderRequest 传递），这很有用。

The above procedure is the most common approach, and it updates the entire scene at each frame. In addition, we provide two functions for finer control. mjv_updateCamera updates only the camera (i.e., maps the abstract mjvCamera to the low-level mjvGLCamera) but does not touch the geoms or lights; alternatively, mjv_camera2GLCamera returns a single mjvGLCamera directly without requiring an mjvScene. This is useful when the user is moving the camera rapidly while the simulation is paused, or when using the Filament renderer where camera parameters are passed via mjrfRenderRequest.

通过操作抽象 geom 的列表，可以实现更高级的渲染效果。例如，用户可以在列表末尾添加自定义 geom。有时我们希望渲染一系列仿真状态（即轨迹），而不仅仅是当前状态。为此，我们提供了函数 mjv_addGeoms，它将当前仿真状态对应的 geom 添加到 mjvScene 中已有的列表中。它不会改变光源列表，因为光照是叠加的，光源过多会使场景过亮。重要的是，用户可以通过枚举类型 mjtCatBit 的位掩码来选择要添加哪些 geom 类别：

More advanced rendering effects can be achieved by manipulating the list of abstract geoms. For example, the user can add custom geoms at the end of the list. Sometimes it is desirable to render a sequence of simulation states (i.e., a trajectory) and not just the current state. For this purpose, we have provided the function mjv_addGeoms which adds the geoms corresponding to the current simulation state to the list already in mjvScene. It does not change the list of lights, because lighting is additive and having too many lights will make the scene too bright. Importantly, the user can select which geom categories will be added, via a bitmask of enum type mjtCatBit:
mjCAT_STATIC

选择属于世界刚体（world body，body id 为 0）的 MuJoCo geom 和 site。

This selects MuJoCo geoms and sites belonging to the world body (which has body id 0).
mjCAT_DYNAMIC

选择属于世界刚体之外的 body 的 MuJoCo geom 和 site。

This selects MuJoCo geoms and sites belonging to bodies other than the world body.
mjCAT_DECOR

选择装饰元素，例如力箭头、自动生成的骨架、等效惯性盒，以及由抽象可视化器添加、与模型中定义的 MuJoCo geom 和 site 并不对应的任何其他元素。

This selects decorative elements such as force arrows, automatically-generated skeletons, equivalent inertia boxes, and any other elements that were added by the abstract visualizer and do not correspond to MuJoCo geoms and sites defined in the model.
mjCAT_ALL

选择以上所有类别。

This selects all of the above categories.

主更新函数 mjv_updateScene 通常以 mjCAT_ALL 调用。它会清空 geom 列表，并调用 mjv_addGeoms，仅为当前模型状态添加 geom。如果我们想渲染轨迹，就必须注意避免视觉上的杂乱。因此合理的做法是：用 mjCAT_ALL 渲染其中一帧（根据用例，通常是第一帧或最后一帧），而用 mjCAT_DYNAMIC 渲染所有其他帧。由于静态/世界对象不会移动，在每一帧中都渲染它们只会拖慢 GPU 并造成视觉走样。至于装饰元素，在某些情形下我们可能想把它们全部渲染出来，例如为了可视化接触力随时间的演变。总之，mjvScene 的构造方式具有很大的灵活性。我们为主要用例提供了自动化，但用户也可以根据需要通过编程方式进行修改。

The main update function mjv_updateScene would normally be called with mjCAT_ALL. It clears the geom list and calls mjv_addGeoms to add only the geoms for the current model state. If we want to render a trajectory, we have to be careful to avoid visual clutter. So it makes sense to render one of the frames with mjCAT_ALL (usually the first or the last depending on the use case), and all other frames with mjCAT_DYNAMIC. Since the static/world objects are not moving, rendering them in each frame will only slow down the GPU and create visual aliasing. As for the decor elements, there could be situations where we want to render all of them - for example to visualize the evolution of contact forces over time. In summary, there is plenty of flexibility in how mjvScene is constructed. We have provided automation for the main use cases, but the user can also make programmatic changes as needed.

虚拟现实#

Virtual reality

在桌面应用中，使用抽象的 mjvCamera 以便直观地用鼠标控制，然后自动将其映射为用于渲染的 mjvGLCamera，是很方便的。在 VR 应用中，情况则大不相同。此时用户的头部/眼睛以及投影面都受到跟踪，因而在房间中具有物理存在。如果有什么东西可以被用户（通过鼠标或其他输入设备）移动，那就是模型相对于房间的位置、朝向和缩放。这称为模型变换，并在 mjvScene 中表示。函数 mjv_moveModel 是控制该变换的鼠标钩子。在更新时使用抽象 mjvCamera 的情况下，模型变换会被自动禁用，方法是设置标志 mjvScene.enabletransform = 0，而不是清除实际参数。这样用户就可以在 VR 和桌面相机模式之间切换，而不会丢失模型变换参数。

In desktop applications it is convenient to use an abstract mjvCamera allowing intuitive mouse control, and then automatically map it to mjvGLCamera used for rendering. In VR applications the situation is very different. In that case the head/eyes of the user as well as the projection surface are being tracked, and therefore have physical presence in the room. If anything can be moved by the user (with a mouse or other input device) it is the position, orientation and scale of the model relative to the room. This is called model transformation, and is represented in mjvScene. The function mjv_moveModel is a mouse hook for controlling this transformation. When using an abstract mjvCamera during update, the model transformation is automatically disabled, by setting the flag mjvScene.enabletransform = 0 rather than clearing the actual parameters. In this way the user can switch between VR and desktop camera mode without losing the model transformation parameters.

由于我们引入了两个空间，即模型空间和房间空间，所以需要在二者之间进行映射，并明确哪些空间量是相对于哪个空间坐标系定义的。仿真器可访问的一切都位于模型空间中。房间空间只有可视化器才能访问。房间空间中定义的量只有 mjvGLCamera 的参数。函数 mjv_room2model、mjv_model2room、mjv_cameraInModel 和 mjv_cameraInRoom 执行必要的变换，VR 应用需要用到它们。

Since we have introduced two spaces, namely model space and room space, we need to map between them as well as clarify which spatial quantities are defined with respect to which spatial frame. Everything accessible by the simulator lives in the model space. The room space is only accessible by the visualizer. The only quantities defined in room space are the mjvGLCamera parameters. The functions mjv_room2model, mjv_model2room, mjv_cameraInModel, and mjv_cameraInRoom perform the necessary transformations, and are needed for VR applications.

虽然 MuJoCo 不提供内置的 VR 应用，但它提供了数据结构和函数，以支持在用户代码中集成 VR。

While MuJoCo does not provide a built-in VR application, it provides data structures and functions to support VR integration in user code.
头部跟踪与相机
Head tracking and cameras

在典型的 VR 应用中，跟踪设备实时提供用户双眼的位置和朝向。这些数据可以直接复制到 mjvScene.camera[n] 中的两个 mjvGLCamera 结构体里（其中 n=0 为左眼，n=1 为右眼）。还必须根据被跟踪显示器的物理特性设置 mjvGLCamera 的视锥参数。

In a typical VR application, a tracking device provides the positions and orientations of the user’s eyes in real-time. These data can be copied directly into the two mjvGLCamera structures in mjvScene.camera[n] (where n=0 is the left eye and n=1 is the right eye). The mjvGLCamera frustum parameters must also be set according to the physical characteristics of the tracked display.
控制器与 mocap 刚体
Controllers and mocap bodies

手持空间控制器同样在房间空间中被跟踪。函数 mjv_room2model 可以将这些位姿映射到模型空间。一旦进入模型空间，控制器的位姿就可以用来更新 MuJoCo 的 mocap 刚体的位置。从物理角度看，mocap 刚体被视为固定的，但用户需要在每个仿真步以编程方式移动它们。它们可以通过接触与仿真相互作用，或者更好的做法是，通过软等式约束连接到与之产生接触的普通 body 上。这提供了有效的动态滤波，并避免了涉及表现得如同无限重的 body 的接触。mocap 刚体随时间变化的位置和朝向存储在 mjData.mocap_pos 和 mjData.mocap_quat 中。

Hand-held spatial controllers are also tracked in room space. The function mjv_room2model can map these poses to model space. Once in model space, the controller poses can be used to update the position of MuJoCo mocap bodies. Mocap bodies are treated as fixed from the viewpoint of physics, yet the user is expected to move them programmatically at each simulation step. They can interact with the simulation through contacts, or better yet, through soft equality constraints to regular bodies which in turn make contacts. This provides effective dynamic filtering and avoids contacts involving bodies that behave as if they are infinitely heavy. The time-varying positions and orientations of the mocap bodies are stored in mjData.mocap_pos and mjData.mocap_quat.
